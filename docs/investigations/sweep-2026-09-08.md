# Sweep of 2026-09-08: the whole suite, one test per run

**Build under test:** `da7323c3a3a6` — *before* the retained-surface write-back
fix (`21cacb354a`). Read every number here as the state that fix was measured
against, not the current one.

**Method:** 1,546 guest runs, each booting a disc that enables one test, so no
result carries a previous test's framebuffer (issue #19). 2,013 captures, 1,871
distinct tests — the suites that could not be split one-test-per-disc appear in
several discs. Scored by `docs/testing/score_sweep.py`; per-test table in
`docs/testing/sweep-2026-09-08-scores.tsv`.

## VERIFIED

| outcome | tests | share |
|---|---|---|
| bit-identical to hardware | 115 | 6.1% |
| near — no channel off by more than 8 | 257 | 13.7% |
| wrong — a feature is off | 1,326 | 70.9% |

**Every one of the 142 repeated captures scored identically to its first run.**
Whatever else is wrong, the renderer is deterministic across boots at this
granularity.

### Blank frames are one defect, not a hundred

173 captures are the test's own label on a flat field. They concentrate:

| suite | blank | of |
|---|---|---|
| `3D_primitive` | 100 | 128 |
| `Depth_buffer` | 24 | 84 |
| `W_buffering` | 24 | 452 |
| `Texture_cubemap` | 23 | 62 |

Every one of those runs logged `Testing completed normally`, so the guest
believes it drew. Scored as pixel difference these read as dozens of subtly
broken tests — `3D_primitive` comes out at "80% of the frame differing across
128 tests" — which is why the scorer separates them. This is the largest single
lever on the board.

## INFERRED

The blank frames in four unrelated suites, all on runs that report completing
normally, look like one mechanism rather than four. Nothing here establishes
which — that needs the reproduction, and `3D_primitive` offers 100 of them.

## UNRESOLVED

**45 tests ran and were never collected** — `Bump_map` (28) and
`Bump_env_lum` (17), in a two-minute window when the sweep and interactive work
were both reaching for the device. Their guest output was overwritten before
collection, and the runner recorded them done regardless. That bookkeeping gap
is real and unfixed. Both suites have complete captures on the post-fix build,
so no measurement is actually missing.

**Three suites did not run one test per disc** — `2D_Lines`, `Attrib_float`,
`Vertex_shader_swizzle_tests`. Contamination *between their own tests* is not
ruled out.

**These figures predate `21cacb354a`.** That fix moved 32 of 339 tests closer
to hardware in its regression run and took `Bump map` from 2/40 to 38/40 on the
palette gate, so any suite reading a texture that overlaps a retired render
target scores worse here than it now deserves.
