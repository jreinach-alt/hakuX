## The standing rule (this file only -- not AGENTS.md; lane.local owns that file)

A registry row with `status == "BELOW_BAR"` and `failing_all == "hitch"` (i.e.
the title's latest scored verdict fails exactly one gate, and that gate is
the loading-hitch gate) is a **single-stall candidate**. From the moment that
verdict lands:

- It must appear in `pm/stall-raised.tsv` (hand-appended; see below) within
  **`STALL_GRACE_S` = 2 hours** ("raise them... not bury it... for days" --
  2h, not days, is deliberately tight; same-day in practice since verdicts
  land during a working session).
- Until it is raised, the hourly report's **STALL ASKS** section names it as
  `NOT RAISED` every hour it runs, and `title_registry.py check --stalls`
  fails the build once the 2h grace has passed.
- Once raised, the row sits with `owner_answer` blank. The hourly report
  names it `WAITING ON OWNER ... raised <N>h ago` every hour until
  `owner_answer`/`answered_pdt` are filled by hand. There is no second grace
  window on the answer side -- the check only enforces the raise, not the
  owner's reply, because the raise is the failure mode this lane was briefed
  to fix (Marvel Nemesis was never *asked*, the owner was never *slow to
  answer* something that reached them).
- A title that fails more than just `hitch` (e.g. `hitch+fps`) is NOT a
  single-stall candidate -- it is a title with other problems too, and the
  existing BELOW_BAR machinery already covers it. This rule is specifically
  for the "it's otherwise fine, it just has one measured stall" case the
  owner called out.

## Next lane / reviewer should not repeat

- Don't conflate this ledger with `pm/stalls.md` / `pm/stall-accepted.tsv`
  (stallwatch). Different mechanism, different failure mode, intentionally
  different section name in the hourly report.
- Don't make `check --stalls` part of the unconditional default `check` path
  without first confirming every host that runs `check` actually has
  `pm/stall-raised.tsv` (even empty-with-header) -- otherwise a bare `check`
  starts failing hosts that were never part of this brief.
- `pm/stall-raised.tsv` and `host-tools/hourly_report.sh` are live,
  non-git-tracked host files edited directly on disk. Nothing in this
  branch's `git diff` will show them; look at `/home/justin/hakux-work/`
  directly, and at the `.bak-20261017-stallraise1017` backup for the
  hourly-report diff.
- The 2h grace is on the *raise*, not the *answer*. Don't add a second grace
  window on `owner_answer` without a separate owner directive -- that is a
  different, unbriefed failure mode (slow owner reply vs. title never
  asked).
