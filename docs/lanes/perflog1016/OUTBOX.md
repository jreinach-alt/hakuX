# lane.perflog1016 OUTBOX

Edits this lane needs in files other lanes hold. Each one is a patch in this
directory, against the base named in PR.md. Apply with
`git apply docs/lanes/perflog1016/<file>.patch`. Each patch is one small
hunk group that reads a flag and does nothing else, so it can go on top of
the holder's work. All four apply together on the base, and the tree builds
both ways with them (`ndk_check.py`, NOTES.md section 5).

NEED: hw/xbox/nv2a/pgraph/profile.c -- REQUIRED for the button to print anything. Without it the switch flips the timers but nothing prints them and nothing polls the marker. The patch adds `#define NV2A_PERFLOG_RT_IMPLEMENTATION` before its first include, which instantiates `nv2a_perflog_set()`/`nv2a_perflog_poll()` from debug.h in this one file. It gates the every-60-frames print block (hakuX-phase, hakuX-cpu, xemu-vsync, xemu-surf, xemu-pace, xemu-work, xemu-gpu) on `nv2a_perflog_on()` instead of `#if NV2A_PERF_LOG`. And it smooths and prints the four once-perf-only phase fields (Sfp/Mfp/FTx/TxH) in both builds, so the hakuX-phase line has one shape. Patch: perflog1016/profile.c.patch
NEED: hw/xbox/nv2a/pgraph/vk/renderer.c -- REQUIRED, one call: `nv2a_perflog_poll(fdump_base_dir())` in fdump_poll_marker(). It runs on the frame dump's existing once-a-second poll, at the flip, with the directory the frame-dump marker already uses. So the perflog marker lives beside frame_dump.on and needs no new JNI or MainActivity edit. Patch: perflog1016/renderer.c.patch
NEED: hw/xbox/nv2a/pfifo.c -- coverage. It switches the hakuX-cpu timers (pusher/puller/method/lock) and the Idle(Fr/St) fields of hakuX-phase at run time. The flag is read once per pfifo_run_puller() call and once per pusher pass, never inside the method loop (class B, see NOTES.md). The callback-latency split (CBL, `#if __ANDROID__ && NV2A_PERF_LOG`) stays a perflog build's. Without the patch those fields print 0 under the switch, and the counts still print. Patch: perflog1016/pfifo.c.patch
NEED: hw/xbox/nv2a/pgraph/vk/surface.c -- coverage. It switches the xemu-surf timers (SURF_TIMER_* and the df flush/read timers) at run time. sdcall/upw stay a perflog build's. Without the patch xemu-surf prints its counts with 0 ms. Patch: perflog1016/surface.c.patch

NEED (lane.local, not a tree file): the owner-play recorder's logcat filter. `ownerplay.py` in lane.local's scratchpad, `LOGCAT_SPEC` at line 35 as read 10-16, keeps hakuX-perf, hakuX-route and hakuX:W. So an owner session keeps the switch's flip line, the Mark lines and `[tcg787]`. It drops all seven tags the switch's every-60-frames block prints. To capture what the button turns on, add `hakuX-phase:I hakuX-cpu:I xemu-vsync:I xemu-surf:I xemu-pace:I xemu-work:I xemu-gpu:I` before `*:S`. With the switch OFF those tags print nothing, so the capture is unchanged until the owner presses the button. The 10-12 capture unit `hakux-ownerplay-perf` had the same gap (its log holds only hakuX-perf/pace/stderr/unhandled/build). The dispatcher's spec (dispatcher.sh:2516) keeps all of them except xemu-vsync and xemu-pace. The ON proof this lane will run reads hakuX-phase, so it is not affected.
