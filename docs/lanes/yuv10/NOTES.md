# lane.yuv10 -- #10 SET_CONTROL0 colour-space conversion

Implements the rules lane.xbox measured on the console on 2026-09-26
(`docs/testing/xbox-csc-2026-09-26.md` on `lane/xbox-csc10`, PR #411).

## Dry run first (2026-09-26)

`docs/lanes/xbox/csc_measured_model.py` at `origin/lane/xbox-csc10`
(`1e6c45dfbd`) against master's goldens: BumpMap_YUY2_L, BumpMap_UYVY_L,
BumpEnvLum_YUY2_L and BumpEnvLum_UYVY_L are each 1,688 wrong of 111,496 quad px
(98.49% exact). That reproduces the brief's figure. It was run before any C
edit.

## What changed

- **nv2a_regs.h.** `NV097_SET_CONTROL0_COLOR_SPACE_CONVERT` is bits 28-31, with
  PASS 0, CRYCB_TO_RGB 1 and SCRYSCB_TO_RGB 2. The brief asked for an
  `NV_PGRAPH_CONTROL_0` home at bits 28-31, but in this tree bits 27-29 of
  that register are already the red, green and blue write enables. The field
  now lives in bits 30-31 (`NV_PGRAPH_CONTROL_0_CSCONVERT`), which were free
  and hold all three values. They are not in `pgraph_reg_dynamic_mask_table`,
  so a change bumps `shader_state_gen`. CONTROL_0 is already on the
  shader-dirty register list.
- **pgraph.c** (the SET_CONTROL0 handler only). The handler stores the field
  and touches nothing else in the file.
- **psh.h / psh.c.** `PshState.color_space_convert` is a `uint32_t` at the
  front of the struct. A uint32 changes `sizeof(PshState)`, so the persisted
  Vulkan shader cache is wiped (`vk/renderer.c`) without a
  `SHADER_STATE_LAYOUT_VERSION` bump in a file this lane does not own.
  - Under CRYCB_TO_RGB, `crycb_to_rgb()` converts every stage that fetched
    (`sampler_type != NULL`). It runs after the whole four-stage loop, so bump,
    luminance and dot-product stages read the raw `tN`.
  - The converter is util.h's integer arithmetic in GLSL ints, with red
    constant 128. `precision highp int` is declared for GLES (common.c), and
    `298*c` needs more than 16 bits.
  - Stages that do not fetch (NONE, PASSTHRU, CLIPPLANE, DOTPRODUCT) are not
    converted. Silicon was not measured on them.
  - SCRYSCB_TO_RGB logs `NV2A_UNIMPLEMENTED` and passes through.
- **Luminance truncation (brief item 4).** PR #168 (`c5f7169e70`) was
  docs-only, so no truncation existed in psh.c. The BUMPENVMAP_LUM product is
  still a float that the framebuffer rounds. It is now floored to a byte
  (`floor(x*255 + 1e-4)/255`), but only when the field is CRYCB_TO_RGB,
  because the converter takes whole bytes. The rest of the Bump env lum
  captures keep rounding: silicon truncates there too (Lum_Off), but changing
  it would move captures this brief says must not move. That is a separate
  lane's arm.
- **texture.c.** YUY2 and UYVY upload raw as (own Y, pair's Cb, pair's Cr,
  255). YUY2 bytes are Y0 Cb Y1 Cr and UYVY bytes are Cb Y0 Cr Y1, the same
  offsets util.h's decoders read. The old decode-at-upload and its comment
  (that "hardware is not returning a TEX1 cell") are retired.

## Texture_format (brief item 3): the field is SET

pbkitplusplus `nv2astate.cpp:810-822` ORs
`NV097_SET_CONTROL0_COLOR_SPACE_CONVERT_CRYCB_TO_RGB` into every SET_CONTROL0
whenever `texture_stage_[0].RequiresColorspaceConversion()`, which is true
for YUY2 and UYVY. So TexFmt_YUY2_L and TexFmt_UYVY_L reach RGB through the
shader converter (rule 1), not the upload. The old upload used red constant
127 and the new converter uses 128. `(409e+127)>>9` and `(409e+128)>>9` differ
only at Cr = 0 (checked over all 256 values). The harness's RGB->YUV never
writes Cr = 0, so both captures are predicted to stay at 0.

## Prediction

`docs/testing/predictions/yuv10-csc.json`, a_ref `43dc17e38b` (the parent),
b_ref `b4850a34eb`. The disc is Bump env lum, Bump map and Texture format.
It is generated by `register.py`, which lists all 80 non-YUV Bump captures by
name from a full-suite arm, because a glob cannot exclude the four.

- The four YUV captures go to **1,576** each. That is the device's
  sign-label floor: BumpMap_A8, BumpEnvLum_A8_L and the Y8/Y16 captures all
  sit at 1,576 (310/422/422/422) on arm `1790404182-arms-y16bump10-fix`. The
  offline model's 1,688 is 422 on all four quads, because the model draws no
  labels.
- **If the arm misses by a few hundred**, the miss is a value, not a
  refutation. The brief's acceptance is <= 2,000. Read the per-quad split
  before touching the mechanism.
- Must-not-move: the other 80 Bump captures, plus TexFmt_YUY2_L and
  TexFmt_UYVY_L.

## Not verified here

- **No GLSL compiler on this host.** The emitted shader was read through
  psh_differ, by temporarily adding the field to its table (not committed).
  The converter text, its placement before `main()`, and the conversion lines
  after the last stage all look right. A compile failure would show on the
  arm as the four captures, and Texture_format's two, going far worse.
- **Desktop not built** (see AGENTS.md). Android builds on the arm.
