Proposed fix hunk for #311 -- NOT APPLIED. accel/tcg/tb-maint.c is
lane.tcgchurn's; this is named here for the board to grant.

Keep a page armed for code-write detection when its last block is discarded.
The next tb_page_add() on that page then finds DIRTY_MEMORY_CODE still clear,
physical_memory_test_and_clear_dirty() returns false, and the whole-TLB walk in
tlb_reset_dirty() does not happen. This restores the arming behaviour the
pre-2af6def68a build had by accident (stranded tier-1 blocks kept the hot pages
non-empty), without the stale-translation bug that fix removed.

Cost it moves elsewhere: stores to a page that once held code keep taking the
notdirty slow path after the code is gone, each finding an empty page list.
On Ghoulies' hot pages that is already the steady state (pr == ev: every
disarm is re-armed within the window). A title that turns a code page into a
hot data buffer pays it; must-not-move rows are Spikeout, RalliSport 2 and a
Crimson Skies soak.

hakux_tlb_protect_calls then counts tb_page_add() calls on an empty page, not
walks; a walk counter belongs inside the `if (dirty)` of
physical_memory_test_and_clear_dirty() for DIRTY_MEMORY_CODE.
