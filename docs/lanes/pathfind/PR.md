`docs/testing/titles/pathfind.py <title> [--device nova|thor] [--budget-min 15] --out <dir>` launches a
title cold and loops screencap -> model -> pad input -> wait. The model is called through `claude -p` with
the frame inline (stream-json): Sonnet 5 per step (3.5-3.9 s measured, vs Haiku 4.5's 6-9 s), Opus 5.5 when
the same screen repeats or a 2-screen cycle is detected, and for the gameplay confirmation. It answers
state / why / action / wait_s. Cheap checks avoid calls: black frames wait, a static load waits, and a
recorded path's matching step replays with no call (own path; a sibling's menu steps at a stricter match).

Gameplay is claimed only when the model says gameplay AND an input visibly moves the playfield: a no-input
control pair, then a frame under the probe; scenes that move by themselves get a left-then-right steering
test; letterboxed frames are vetoed; and 30 s later the frame must still be play, or the claim is retracted
and the loop goes on. Every call is logged to `<out>/calls.jsonl`; a success writes
`pathknow/paths/<TITLEID>.json`; a failure writes a loop-free partial path for the retry.

Scoreboard (lot of the brief's never-routed Nova titles, seeded shuffle; table in NOTES.md, regenerated by
`docs/lanes/pathfind/scoreboard.py`): see NOTES.md. Each success's frame strip is in
`docs/lanes/pathfind/runs/<title>/strip.jpg`, reviewed by eye; one false pass (Bruce Lee) was caught in that
review and fixed.
