## Proposed change

At `hw/xbox/nv2a/pgraph/vk/texture.c:4039` (`create_texture`) surface-to-texture is taken only when
`state.levels == 1`. Otherwise a draw-dirty surface over the texture is read back at `texture.c:4084-4096`
(`tsc.sdl++`, `pgraph_vk_surface_download_if_dirty` -> `download_surface(force)` `surface.c:2797` ->
`download_surface_to_buffer` `surface.c:2244`, a SURFACE_DOWN finish counted as `[sdcall] tobuf`), and the texture
is re-uploaded from VRAM. The proposal replaced that read-back, when no level 1..n had a CPU write
(`check_texture_dirty`), with a GPU-built image: surface -> level 0, then a linear blit chain for levels 1..n.

## Why the change is not built

**1. The read-back it removes is already gone on master.** Before texscan2d (owner capture 2026-10-18, build
72af9cb92c, `/home/justin/hakux-work/captures/fps-owner-1018/fable.txt`) the texture at `@187d080` (`fmt0x6
128x128 levels3`, swizzled) had three draw-dirty surfaces over it: `@187d080` 128x128 (level 0, `sdl`),
`@188d080` 64x64 at `off+65536` (level 1) and `@1891080` 32x32 at `off+81920` (level 2); the same three shapes at
`@18a7080`. On the 10-19 run with texscan2d (`711315bbe7`-perflog,
`/home/justin/hakux-work/captures/fpsnext1019/runs/fable-h2/logcat.txt`, Oakvale walk):

- `[texscan] on 2d=1`; `[texscan] first copy tex @187d080 128x128 fmt0x6 faces0x7 levels3 lin0`;
- `[tsc] sdl0` and `cls[base0 ... mip0]` in all 144 `[tsc]` lines;
- the 26 gameplay windows (12:29:18-12:30:44): `ts[bind188-201 cp453-486 keep81-141]`, `ts2[mip188-201 fb0]`.

**2. A generated chain would replace guest-drawn levels.** texscan plans a slot only for a draw-dirty surface
(`texture.c:2267-2293`), and each slot is counted once per bind as `cp` (copied) or `keep` (unchanged since its last
copy). `cp + keep` is 3.0 per bind in every gameplay window (e.g. 453 + 141 over 198 binds), so at nearly every
bind levels 1 and 2 hold GPU-drawn content newer than VRAM. Those levels are written by the GPU, not the CPU, so
`check_texture_dirty` on their VRAM ranges passes and the proposed `cpuw` fallback would not fire; the linear blit
chain would overwrite the guest's own level 1 and 2 pixels. Where a level has no surface, its VRAM content is what NV2A samples, and texscan already uploads it as is;
a generated chain is less faithful there too, not "at worst as faithful". Built where proposed (the `levels > 1`
branch, ahead of `texscan_prepare` at `texture.c:4073-4076`), it would take these binds from texscan.

## What drives Fable's remaining `tobuf`

The `[sdcall]` field `tobuf` does not name its caller; the `hakuX-stall` line does
(`hw/xbox/nv2a/pgraph/vk/draw.c:998-1033`, `dlSrc[...]`, `dif[...]`). In the same 26 windows:

| Counter | Range per 60 frames |
|---|---|
| `[sdcall] tobuf` fin / fence / ms | 18-37 / 0 / 412.6-905.2 (mean 562.6, 9.4 ms/flip) |
| `sd[dl]` (`sd_dl_to_buf`, `surface.c:2763`) | 18-37, equal to `tobuf` fin in every window |
| `dlSrc[defFb ppdFb dirtyIf]` | 0 / 0 / 18-37: every one through `pgraph_vk_surface_download_if_dirty` (`surface.c:4631`) |
| `dif[ovl ovlSh exp expSh blt flu dds oth]` (calls, dirty or not) | 590-632 / 78-97 / 0 / 1-4 / 0 / 0 / 0 / 0 |
| `[sdcall] surfupd` fin / ms | 118-124 / 1048.1-1501.9 (mean 1319.5, 22.0 ms/flip) |
| `evict[dl]` (`sd_eviction_dl`, deferred) | 713-767 |

With `blt`, `flu`, `dds`, `oth`, `exp` and `[tsc] sdl` all 0, the synchronous downloads come from the shelved
loops: `invalidate_overlapping_surfaces` (`surface.c:4060-4078`, `ovlSh`, 78-97 calls) and `expire_old_surfaces`
(`surface.c:4590-4605`, `expSh`, at most 4). At least 14-33 of each window's 18-37 are therefore shelved surfaces
overlapped by a new surface and downloaded inline before their images are destroyed. The active-surface overlaps
(`ovl`, 590-632; `evict[dl]` 713-767) go deferred and complete in `surfupd`. Neither site is in
`create_texture`.
