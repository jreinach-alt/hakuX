# Audit pass 1: PR #479 (lane/forza414), 2026-09-27

Diff read: `origin/master...eae1cf616e`, code in `hw/xbox/nv2a/pgraph/vk/surface.c`
and `hw/xbox/nv2a/pgraph/vk/draw.c`. Result: **1 HIGH, 1 MEDIUM, 1 LOW** →
`needs-remediation`.

The cut changes one invariant that the rest of surface.c relies on. Before it,
every `pgraph_vk_surface_update` completed the recorded downloads before
returning, so no download was still pending when the next method ran. Now a
download stays pending across methods until the next finish. The PR guards the
readers of guest memory (the range lookup, the CPU-access callback, the flip
pre-download and expiry), and those guards look right. It does not guard the
lifecycle of the `SurfaceBinding` struct a pending download points to
(`dl->surface`). `download_surface_deferred`'s own header states the contract
the cut now breaks: "The caller MUST ensure
pgraph_vk_download_surface_complete_deferred() is called before the surface
is invalidated or freed."

## HIGH 1: a pending download's struct is reused, and its completion retires the new binding's draws

`surface.c`, `update_surface_part` should_create branch (`get_shelved_surface`
/ `get_any_compatible_invalid_surface`, then `unregister_cpu_access_callback(surface); *surface = target;`),
together with `pgraph_vk_complete_staged_downloads` (lines ~941-970).

Both reuse paths return an existing struct and overwrite it with `target`,
which `pgraph_vk_surface_update` zeroes, so `draw_generation` restarts at 0.
Nothing touches `r->deferred_downloads[i].surface`, so a download still pending
from the struct's previous life now points at the new binding. When the
download retires, `complete_staged_downloads` applies the old binding's
generation to the new one:
`s->download_generation = dl->draw_generation; if (s->draw_generation == dl->draw_generation) s->draw_dirty = false;`

Failure scenario (the ping-pong this PR targets, so it happens on the shipping
path, not a corner):
1. Method m: the colour target at address A changes format F1→F2. The F1
   binding S (draw_dirty, `draw_generation` = g, drawn in an earlier, submitted
   command buffer) is evicted: `download_surface_deferred(S)` records its
   download, and S is shelved. The F2 binding has nothing to upload
   (`upload_pending` false: unshelved clean, handed off, or this is one of the
   `surface_update(d, false, ...)` setter calls in pgraph.c). So
   `surface_update_may_defer_downloads` returns true and the download stays
   pending.
2. Method m+k, no finish in between: the target at A goes back to F1.
   `get_shelved_surface` returns S's struct and `*S = target` makes it T,
   with `draw_generation` 0. It comes off the shelf clean (`vram_newer` is not
   set, because `surface_vram_written` excludes S itself; under TCG
   `mem_dirty` is false), so the update defers again.
3. The title draws g times into T, the same count it drew into S last frame.
   T's `draw_generation` is now g.
4. The next finish retires the batch. `dl->surface == T` and
   `dl->draw_generation == T->draw_generation`, so `T->draw_dirty = false`
   and `download_generation = g`, but VRAM holds S's pixels, not T's.
5. A guest read of A (the CPU-access callback checks
   `draw_dirty && download_generation != draw_generation`, texture fallbacks
   check `draw_dirty`) finds T clean and never downloads it. The guest reads
   the previous frame's target.

The invalid-list path (`get_any_compatible_invalid_surface`) does the same
thing with more consequences. A surface invalidated by an overlapping put
while its draws are in a submitted command buffer gets
`invalidation_frame = -1`, so `surface_in_flight` says it is free. Reusing it:
(a) calls `unregister_cpu_access_callback`, which drops the only watch on the
pending download's destination, so a guest write there before the finish is
overwritten when the download lands, and a guest read sees memory from before
it; (b) makes the completion mark VGA/NV2A_TEX dirty over the *new* binding's
range, not the one the download wrote, so the texture cache is not told that
the old range changed; (c) the same generation collision as above.

Before this PR the window was one `surface_update` (and a same-address
unshelve cannot happen inside the update that shelved the struct, because the
eviction means the formats differ), so none of this could occur. The goldens
are byte-identical because nothing in the 266 captures reads a ping-ponged
target back through the CPU inside a deferral window.

Remedy: make a struct that a pending download references ineligible for reuse
until the batch retires, or complete the batch first. The cheapest way is to
treat it as in flight: have `surface_in_flight` / `get_shelved_surface` check
`dl->surface` (at most `MAX_DEFERRED_DOWNLOADS` entries), or call
`download_surface_complete_deferred(d, ...)` before the `*surface = target`
when any pending entry points at `surface`. Detaching with
`deferred_downloads_clear_surface` alone is not enough, because it also loses
the dirty marks (see MEDIUM 1).

## MEDIUM 1: prune_invalid_surfaces frees a pending download's surface, dropping its watch and its dirty marks

`surface.c` `prune_invalid_surfaces`, called at the end of every
`pgraph_vk_surface_update`, *after* the new deferral decision.

With more than `num_invalid_surfaces_to_keep` (10) invalid surfaces, the
oldest ones not `surface_in_flight` (again: `invalidation_frame == -1` when
their draws predate the current command buffer) are freed. For one with a
pending download, `deferred_downloads_clear_surface` nulls `dl->surface` and
`unregister_cpu_access_callback` drops its watch. Until the next finish:
- a guest write to that range is not trapped, and the download lands over it
  when it retires; a guest read is not trapped and reads memory from before the
  download (the surface_access_callback guard only runs if a watch fires);
- at retirement `complete_staged_downloads` skips both
  `memory_region_set_client_dirty` calls because `dl->surface` is NULL, so
  `DIRTY_MEMORY_NV2A_TEX` never learns that the range changed and a texture
  cached from it stays stale.

Bounded blast radius, because it needs 10+ invalid surfaces with a pending one
among the oldest. Before this PR a prune could not see a pending download,
because the batch had completed earlier in the same update. Remedy: skip a
surface a pending download references (the same test as HIGH 1), and take the
dirty range from `dl->dest_ptr`/size rather than from `dl->surface`, so a
detached download still marks what it wrote.

## LOW 1: a partial-mask clear resets the other binding's `cleared`

`draw.c` `mark_clear_full`: it assigns `cleared` for both bindings on every
clear. A zeta-only clear leaves the colour binding's content alone, but it
sets `color_binding->cleared = false` (all_channels is false). That is
conservative, not wrong: it loses the linear-to-swizzled rescue for a colour
target fully cleared earlier and then followed by a depth-only clear, which is
a common order. Only touch the binding(s) this clear writes (`write_color` /
`write_zeta`).

## Checked and clean

- `deferred_downloads_overlap_range`: the lengths match what
  `complete_staged_downloads` writes (swizzled `w*h*bpp`, linear
  `pitch*height`), and the half-open overlap test is correct.
- Range lookup: textures (the scan cache is invalidated by the
  `surface_list_gen` bump every eviction makes), vertices, and blits all reach
  the overlap check.
- `surface_access_callback` → `downloads_pending` → the PFIFO thread's
  `pgraph_vk_process_pending_downloads` completes the batch first
  (`SDC_PENDING`).
- The `!tcg_enabled()` exclusion is correct: without the watch, VRAM must be
  current on return.
- `pgraph_vk_prerecord_display_download` sharing an unsubmitted batch: the
  flip's fence covers both.
- `expire_old_surfaces`: it completes before any active expiry is invalidated
  and before the first shelved free. Image destruction is fence-deferred
  (`DeferredSurfaceRelease`), so recorded copies never outlive their VkImage.
- `invalidate_overlapping_surfaces`' shelved branch: a pending shelved
  surface is still `draw_dirty`, so `download_if_dirty` completes the batch
  before the free. That is correct, but it adds a redundant synchronous
  download.
- Hunk 3 (`flush_draw_one_pass`): the four saved fields match the four
  asserts exactly, with the same read accessor.
- The `[sdcall]` probe is compiled only under `NV2A_PERF_LOG && __ANDROID__`
  and has no side effects outside its counters.
