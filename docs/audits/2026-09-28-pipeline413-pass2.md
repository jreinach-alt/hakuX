# Audit pass 2, second round: PR #541 at `2f38c02487`

**Verdict: clean. All four pass-1 scenarios are now fixed, so none of them can occur.** The
remediation commit `2f38c02487` touches only the four places named above: a comment,
a JSON field, NOTES prose and the lane's reader script. It changes no code path.

## LOW-1: fixed

The comment at `profile.c:639-643` and NOTES §1 now say a miss is counted only when
`vkCreateGraphicsPipelines` runs inline, and that an async enqueue returns before the count.
NOTES "Do not" adds that `dpm` from an async run must not be read as "no compiles". An

world. `grep "async enqueue"` finds only the new warning.

## LOW-2: fixed

`registered_utc` is now `2026-09-28T04:53:04Z`. That equals the commit time of `601b38005e`
(21:53:04-07:00) and comes before the pilot was queued at 04:53:10Z. The file is valid JSON.
`a_ref == b_ref` is unchanged, so it still queues no arm.

## LOW-3: fixed

§7 now calls all three figures upper bounds (`<= 485`, `<= 780`, `<= 1.24 s`, excess / miss).
It says co-occurrence cannot separate compile time from other load work, and it names `dpc_ms`
(§9) as the measurement. It also records that the 2105 ms floor window has `dpm=2`. A "Do not"
line forbids quoting them as measured cost. The PR body's "414-485 ms per pipeline" is P2's
registered quantity, `(dt_ms - floor) / dpm`, scored as written. It is not a claim about compile
cost, so it is not a finding.

## LOW-4: fixed, and the leg can fail

`parse()` now adds 86400 s whenever the clock drops by more than half a day. The new selftest
shifts the fixture so that it starts at 23:59, and checks that the crossing happens, that the
base rate is 1.0/s, that there is one stall, and that the mark stays 64 s after t0. `--selftest`
passes on this head. With `day += 86400` changed to `day += 0`, two of those legs FAIL
(base rate and stall; mark offset), so the legs do discriminate. Small backward steps from
reordered logcat lines stay far under the 43200 s threshold, so they cannot trip it.
