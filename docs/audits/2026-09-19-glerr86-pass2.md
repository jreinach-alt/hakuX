## M1 — CLOSED. The shared slot is gone, and the scenario that flooded now
emits 257 lines

Pass 1's scenario: eight or more distinct GL error enums over a process
lifetime, after which two codes alternate through the shared last slot of
`seen[8]`, re-key each other, and print `occurrence=1` on every shader load
forever.

The remediation did not repair the table; it removed it (`shaders.c:146-177`).
There is one `static uint64_t printed`, no key, and therefore no slot to
share. `is_power_of_ten` is deleted.

I verified this by compiling the **live** sliced block against my own stubs —
not the lane's harness, so that the check and the thing checked have different
authors — and driving pass 1's exact scenario 25× past the point at which the
old code flooded:

```
after 9 distinct enums: lines=9
after 5000 alternating loads: lines=257 stop_lines=1
ok  M1: 5009 loads alternating past the budget emit budget+1 lines, not 5009
ok  M1: exactly one line ever reports index 1 (the counter never re-keys)
ok  M1: every report index is strictly greater than the one before it
ok  the 'no longer logged' line is printed once, not once per error
ok  past the budget a two-deep backlog is still fully drained
ok  and silently: no further lines after the stop line
```

The same probe against the block at `7809361a34` — pass 1's subject, sliced by
the same anchors — prints **5008** lines for the same drive, with no stop line.
So the probe separates the two blocks rather than passing for free.

The budget arithmetic is exact and has no overflow. `printed` reaches
`MAX + 1 == 257` on the error that prints the stop line and is never
incremented again: the guard at `:157` returns before `:160` can touch it. The
stop line therefore prints exactly once per process, and the count is
`ANDROID_GLERR_MAX_REPORTS + 1` and nothing else. The comment at `:148-151` now
describes what the code does, which is the other half of what pass 1 asked for.

**Concurrency unchanged and still safe.** `printed` is static mutable state,
as `seen[]` was. `pgraph_gl_shader_load_from_memory` still has exactly one
caller in the tree (`shaders.c:1002`, the only reference outside its

## N1 — new, LOW, OPEN. The budget is enum-blind and permanent, so one noisy
code can spend it before a rarer one is ever seen

`shaders.c:157-167`. The budget counts lines, not codes. A renderer that
leaves `GL_INVALID_OPERATION` pending at 256 shader loads — front-loaded into
the first seconds, which is exactly when cache misses happen — exhausts the
budget, and a `GL_OUT_OF_MEMORY` or `GL_CONTEXT_LOST` arriving later never
reaches a `[glerr]` line at all. The old per-enum scheme, for all of M1, would
have printed the first occurrence of each distinct code.

**Failure scenario.** A device run on a badly-broken renderer: the log's first
257 `[glerr]` lines all name one code and one repeated cause, the stop line
appears, and the rarer error that would have identified the actual fault is
silently outside the budget. The reader sees a stop line and has no way to
know whether what followed was more of the same or something new.

**Why LOW and not MEDIUM.** Nothing the emulator computes is affected — the
drain runs past the budget unconditionally (`:158` `continue`s inside the
`while`, verified above), so the `glGetError` after `glProgramBinary()` is as
honest after exhaustion as before. And the error itself is not lost from
logcat: `android_log_apply_uniform_entry_errors` at `:901` prints every
drained error on every bind, ungated and **unbounded**, so a later
`GL_OUT_OF_MEMORY` still appears as `GL error 0x505 before
apply_uniform_updates:...`. What the budget can cost is the `[glerr]` framing
— the shader hash and the "pending at a load" attribution — not the existence
of the error in the log. `NOTES.md:192-197` already tells the reader that the
stop line appearing at all is itself the finding.

**Remediation, if anyone takes it:** reserve a small number of the budget for
first-sightings of a code not yet printed, or say in the docstring that the
budget is deliberately enum-blind and why. Not worth holding the fold for;
the docstring at `:137-142` already frames the budget as a bound on the
unreasonable case rather than a diagnostic policy.
