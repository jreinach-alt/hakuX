## MEDIUM 1 — `changed_region()` ignores `--extent-rule`, so the mode this diff now mandates is the one whose scoping check misfires

`docs/testing/line_priority_arms.py:159`

`decisive_xy()` is given the run's footprint rule (`line_priority_arms.py:221`
passes `a.extent_rule` through to `lp.field(e, w, bias, lp.MARGIN,
extent_rule)`). `changed_region()`, four functions below, hard-codes it:

```python
def changed_region(w):
    """Union of the footprints of every edge whose ORDER prim_rewrite.c picks,
    dilated by one pixel.  Nothing outside this can move when only the order of
    those edges changes, so a difference outside it is a scoping bug."""
    ...
            c, _, _, _ = lp.field(e, w, bias, 0.0, False)   # <-- never the rule
```

So under `--extent-rule` the decisive set is built from the wide
(hypot-approximation) footprint we actually draw, while the region those
pixels are allowed to live in is built from the narrow perpendicular one. The
margin between the two grows with width, and the one-pixel dilation stops
covering it somewhere around w = 40.

**This is not latent — it fires on this PR's own judged command.** The diff's
new `line_priority_arms.py` docstring is headed `WHICH FOOTPRINT: PASS
--extent-rule`, and the prediction's `THE JUDGED COMMAND` names
`--extent-rule` too. Running exactly that command on this arm's two result
directories:

| w | `outside` as shipped | `outside` with the rule threaded through |
|---:|---:|---:|
| 8 – 32 | 0 | 0 |
| 40 | 1 | 0 |
| 48 | 2 | 0 |
| 56 | 5 | 0 |
| 57 – 59 | 6, 6, 7 | 0 |
| 60 – 63 | 7, 8, 8, 9 | 0 |
| 63.125 – 63.875 | 8, 8, 8, 8, 8, 9, 9 | 0 |

12 of 27 captures violate an invariant the tool's own footnote states as
`It must be 0`.

**The cause is confirmed, not inferred.** I copied the tool, threaded
`extent_rule` into `changed_region()` (3 lines: signature, the `field()` call,
the call site at :246), re-ran the identical command, and diffed the output.
Every `outside` became 0 and **nothing else changed at all** — the eleven-class
table, every per-capture `decisive`, `moved` and `A!=B px` are identical. The
scratch copy was deleted; it is not in this branch.

**Failure scenario.** The next person to judge an arm the way this diff tells
them to gets a violated must-be-zero scoping check with no explanation
anywhere in the lane's record, and either (a) spends a remediation cycle
looking for an emulator scoping escape that does not exist, or (b) learns that
`outside` is noisy and stops reading it — after which a real scoping escape,
which is the only thing that column exists to catch, passes silently. (b) is
the expensive one, and it is the one that actually happens: this PR's own
record already contains a judged run nobody reconciled.

**Remediation.** Thread the rule through `changed_region()`. Three lines. If
the lane disagrees — e.g. it wants the perpendicular region deliberately, as a
conservative over-report — then say so in the footnote next to `It must be 0`,
because the sentence as written is then false.

*Second-order, worth stating because it is good news and it is measured: with
the region computed on the right footprint, this patch touches **nothing**
outside the reordered edges' own pixels, on all 27 captures. The scoping claim
the arm's `must_not_move` globs can only partly cover is now positively
established for `Line width` as well.*

## What I checked and found correct, so remediation does not re-derive it

1. **The predicate matches its reader exactly, with no third state.** I went
   looking for the case where `pv_placement_observable()` drops the rotation
   while `geom.c` still spells `provoking_index` as the literal `0` — that
   would be a silent wrong flat colour on every wireframe fan. It cannot
   arise: `NV_PGRAPH_CONTROL_3_SHADEMODE` is a **single bit**
   (`nv2a_regs.h:499-501`, FLAT = 0, SMOOTH = 1), `prim_rewrite`'s
   `flat_shading` is `== FLAT` (`vk/draw.c:5081`, `gl/draw.c:749`) and
   `geom.c:40`'s `smooth_shading` is `== SMOOTH`, so one is exactly the
   negation of the other. `NV097_SET_SHADE_MODE` discards any other parameter
   (`pgraph.c:3057-3072`) and reset writes SMOOTH.
2. **Rotation preserves every edge's ordered pair.** `geom.c:224-226` emits
   `(1,2) (2,0) (0,1)`; rotating `(A,B,C) → (B,C,A)` maps that to
   `(C,A) (A,B) (B,C)` — the same three ordered pairs, re-ranked. So every
   per-edge flat source is unchanged under *either* provoking convention,
   which is what makes the Android-GLES last-vertex default (the diff's LOW 1
   from pass 1) not reach the conclusion. Checked against
   `fog_special_index` = `"index"` on the non-widened path (`geom.c:438`) and
   the edge's own `i0` on the widened one (`geom.c:551`).
3. **Keeping the rotation under FILL/POINT is load-bearing even under SMOOTH**,
   and the comment's reason is right: `vtxFogSpecial` is `flat` in every shade
   mode, and a FILL triangle's flat source *is* output index 0 — unlike a
   line's, which is per-edge. So the predicate's `polygon_mode != POLY_MODE_LINE`
   term is not merely conservative.
4. **One call site, one primitive, identical counts.** `pv_placement_observable()`
   is called only at `prim_rewrite.c:589-590` for `PRIM_TYPE_TRIANGLE_FAN`;
   `max_output_indices()` is untouched and both branches emit 3 indices per
   triangle, so no buffer-capacity or counter consequence. `needs_rewrite()`
   returns true for the fan unconditionally, so the new branch is reachable.
5. **`line_priority.py`'s derived `prim_rewrite()` reproduces the C**, hand-checked
   per block rather than trusted: `LLoop` under **both** conventions against
   `rewrite_line_loop()` + `emit_line_pv()` including the closing edge's
   reversal; `TFan`'s `(v2, hub, v1)` against `emit_tri_pv()`'s `p == c`
   branch; `Quad` against `rewrite_quads_line()`; `QStrip` against
   `rewrite_quad_strip_line()`; `Poly` against `rewrite_polygon_line()`'s
   both-conditions-in-one-iteration loop; `Tri` as a pass-through under
   `needs_rewrite()`. `order_for()`'s group-local `frozenset` matching is
   guarded by `assert len(grp) == size` and `assert sorted(out) == range(n)`,
   which is what the old index arithmetic lacked.
6. **Calibration 3 re-run independently**, not read: `patched_order(block) ==
   order_for(block, "opp_abc")` for all six blocks, and `!= order_for(block,
   "ours")` for `TFan` alone. The patch becomes the derived rule rather than
   approximating it, as claimed.
7. **`Files:` matches** `git diff --stat origin/master...HEAD` (12 paths) —
   this record adds two more, and the body needs extending with them.
8. **Numbers stated in more than one place agree.** The `+12 / +10` LOW-2
   correction is annotated **in place** at `NOTES.md:120` where the superseded
   table is read, not only appended below it — which is the failure mode that
   made pass 2 file a MEDIUM.
