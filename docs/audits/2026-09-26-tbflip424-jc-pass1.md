# Audit pass 1: PR #465 lane.tbflip424 (#425, HAKUX_TCG68_JC on by default)

Head audited: `cf09ea47a1` on base `origin/master` `e5db66fa37`. Diff: `accel/tcg/cputlb.c` +4 -1.

**Result: no HIGH, no MEDIUM, two LOW.** Next label: `needs-audit-2`.

## What the diff does

`hakux_tlb68_jc_on()` now returns 1 when `HAKUX_TCG68_JC` is unset. When it is
set, the old parser `hakux_tlb68_env()` still decides, so `"1"` gives on and
any other value gives off. The header comment gets three lines saying so. The
cached `-1` / `qatomic_set` pattern is unchanged: two threads racing the first
read both compute the same value, so the race is harmless.

## Readers of the switch (all checked at head)

- `tb-maint.c:1487` `tb_jmp_cache_inval_tb()`: the only place behaviour
  changes. Its safety argument (tb_lookup's exact cflags compare rejects a

  `2026-09-25-tcgchurn-pass1.md` and `2026-09-26-jcache425-pass2.md` for

- `translate-all.c:1009`: the orphaned-recycle path puts CF_INVALID back

- `cputlb.c:298` and `cpu-exec.c:1053`: log lines that print the switch
  state. No logic depends on them.
- Registered predictions (`jcache425-crimson.json`,
  `jcache425-pixels-inert.json`) describe "unset = wipe", but they are pinned
  to `1b43be6b3a`. They are about that binary and are not re-queued against

- No test under `tests/`, `docs/testing/*.py` or `docs/testing/*.sh` reads
  the switch.

## Findings

### LOW-1: any set value other than "1" now turns the fix off, not only "0"

The PR body and the new comment say `"0"` turns it off. What the code does is
turn it off for any value that is set and is not `"1"`: `""`, `"on"`, `"true"`
and `"yes"` all give off. Scenario: a user's Android `env_vars` preference
contains `HAKUX_TCG68_JC=` (empty) or `HAKUX_TCG68_JC=on`. The loop at
`xemu_android.cpp:806` calls `setenv` with that value, `getenv` returns
non-NULL, the parser returns 0, and the wipe comes back. The blast radius is
performance only: the result is master's pre-PR behaviour, which is the safe
direction. Suggested fix: document it as "unset or `1` = on, anything else =
off", or parse `"0"` as the only off value.

### LOW-2: the block comment's lead sentence still says "Default OFF"

`cputlb.c:154-156` still reads "Default OFF (#311 arms must differ from
master only by counters and one hunk); "1" turns a fix on". That now holds
for `HAKUX_TCG68_RD` only. The per-switch line added under `JC` corrects it,
but a reader who stops at the lead sentence gets the wrong default. Suggested
fix: "Default OFF except where noted".
