## Pass-1 findings: re-checked, and a decision for each

**LOW-1 (the SFP push-descriptor bind can change `texX1A7` without a uniform
upload).** I re-checked that it is unreachable, including a path pass 1 did
not name. For the SFP to rebind and then return, `texture_state_gen` has to
move while `any_reg_gen` and `pipeline_state_dirty` stay put. There are three
places that move the texture gen:

- `pgraph_reg_w` / `pgraph_reg_w_atomic` (`pgraph.h:473`, `:510`). These
  always bump `any_reg_gen` in the same call, so `draw.c:3985` clears
  `sfp_ok`. The full path then uploads the uniforms (`create_pipeline`: the
  early hit calls `pgraph_vk_update_shader_uniforms` at `:2093`, and a miss
  calls it at `:2123` or through `bind_shaders`).
- `pgraph_vk_texture_surface_view_retired` (`texture.c:3123`). This also sets
  `pipeline_state_dirty`, so the SFP misses at `draw.c:3896` before it reaches
  the bind.
- The draw-queue flush (`draw.c:5322`). It sets `any_reg_gen` to
  `last_any_reg_gen`, which could look like an opening. It is not one: a draw
  enters the queue only when `texture_state_gen == q->texture_state_gen`
  (`check_draw_mergeable`, `:4980`). `q->texture_state_gen` is taken just
  after a direct `pgraph_vk_flush_draw` that bound textures at that gen
  (`:6565-6573`). So at flush time the gen equals `last_texture_state_gen`
  and the SFP does not rebind. The per-entry UBOs are uploaded at enqueue
  (`upload_draw_uniforms`), under the same binding, so they carry the right
  mode.

*Decision:* not remediated before fold. The invariant that stands in for a
guard is "the texture gen never moves alone": every current bump comes with
`any_reg_gen` or `pipeline_state_dirty`. If a future change adds a bump
without either, pass 1's one-line fix applies: in the `draw.c:3952` branch,
clear `sfp_ok` when a stage's X1A7 mode changed. The finding stays LOW.

**LOW-2 (the rule is applied whichever way the image was filled, so it would
apply twice once the write side lands).** It cannot happen on this head. The
download still writes the host byte unchanged (`vk/constants.h:632`, "Not
implemented"), so both fills hold `h`.

*Decision:* deferred to the write-side arm, which the PR body names as the
next step. That arm has to change the gate in `create_texture()` so it
applies the rule only when the image came from the surface's host image (or
it has to stop the rule for VRAM-filled textures some other way). Otherwise
`_O` alpha reads about 0.75 instead of 1.0. The `constants.h:632` comment will
need updating in the same change, because the read side is now implemented.

**LOW-3 (GL uploads `g_tex_x1a7_readback`, which only VK writes).** This is
unchanged: `psh.c:255` is file-static, `psh.c:4390` reads it for both
renderers, and nothing under `pgraph/gl/` writes it. The only way to reach it
is a live Vulkan→OpenGL switch on desktop (`renderer_switch_phase`,
`pgraph.c:1100`) after an X1A7 bind. Android picks one renderer at start-up,
so the shipping target cannot reach it.

*Decision:* not remediated before fold, because the shipping target cannot
reach it. The follow-up is to zero the array at renderer init. It is small
and can ride with the write-side arm, which touches the same code.
