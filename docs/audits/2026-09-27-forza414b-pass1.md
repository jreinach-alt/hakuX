# Audit pass 1: PR #518 (lane/forza414b)

PR: #518, "lane.forza414b: #414 upload_pending setter split; display pre-download deferral"
Head audited: 603c57ca0e (merge base with master 4fcbe0262e)
Scope: the diff against master: `hw/xbox/nv2a/pgraph/vk/surface.c`, three
predictions under `docs/testing/predictions/forza414-predl-*.json`, and lane
notes/tools under `docs/lanes/forza414/`.

Verdict: **one MEDIUM, two LOW. needs-remediation.**

## What the change does

1. The flip's pre-recorded download batch (`pgraph_vk_prerecord_display_download`)
   used to complete at the first `surface_update` after the flip, which waited
   on the flip's fence (~51 ms/frame on DOA). Now `surface_update_may_defer_downloads`
   lets it stay pending across draws. It completes when a consumer needs it:
   an overlapping range lookup, the CPU-access watch, scanout, a new recorded
   download (`complete_submitted_downloads`), the frame-slot rotation, or at
   the latest the next flip's pre-record (`SDC_PREREC`).
2. `pgraph_vk_download_surfaces_in_range_if_dirty` no longer completes a
   submitted batch on every lookup. It completes it only when it overlaps the
   range or when a new download gets recorded.
3. The display surface is no longer marked clean at its *current* generation
   when the batch completes. Its batch entry retires it at the generation the
   copy captured. `complete_staged_downloads` now clears
   `display_predownload_*` wherever the batch completes (draw.c's finish and
   rotation paths included). Before this, those paths left the flag set.
4. Perflog-only: the `[sdcall]` `why=` split of `upload_pending` setters, the
   `clr/clrfull` counters, and the `record`/`prerec` callers.

## Checked and found sound

- **Ordering of a new record behind the submitted batch.** Every
  staging-buffer record goes through `download_surface_record_deferred`, and
  that calls `complete_submitted_downloads` first. So one fence still covers
  every entry, and a new copy cannot be read before its GPU write.
  `download_surface_deferred` re-tests dirtiness after that completion, so a
  surface whose copy was already in the batch is not recorded twice.
- **Readers of VRAM while the batch is pending.**
  - Texture, vertex and blit ranges: blit.c tests both source and dest
    through the range lookup, and the lookup's final
    `deferred_downloads_overlap_range` test completes the batch.
  - CPU access: `wait_for_downloads` in `surface_access_callback` does the same.
  - Synchronous `download_surface`: `download_surface_to_buffer` completes first.
  - Scanout: `pgraph_vk_process_pending_downloads` completes first.
  - `surface_update` uploads: the gate still returns false when a bound
    binding has `upload_pending`, and the upload runs after the gate.
- **Fence-slot reuse.** `display_predownload_frame_index` and
  `deferred_downloads_frame` name the same slot: prerecord runs in the
  flip's command buffer, and that buffer's finish stamps it. The rotation in
  draw.c completes the batch before it resets that slot's fence.
- **Generation retire.** Removing the "clean at current generation" block is
  correct. A draw landed after the flip is no longer dropped from the next
  download. The per-entry code keeps `draw_dirty` when
  `draw_generation != dl->draw_generation`.
- **Locking of the perflog map.** `g_upw_map` is written from
  `surface_access_callback` and `surface_watch_rearmed`. Both take
  `pgraph_lock_settled` first, so the "only under pgraph.lock" comment holds.
- **`[sdcall]` names array vs enum.** 13 names for 13 callers, in order.
- **Predictions.** Each leg names the world it fails in (W1: a consumer
  completes the batch soon after the flip anyway; G0: the hunk does not reach
  AUF, so B is inert rather than refuted). The must-not-move guard names the
  suites a missed consumer would move, and `skip_tests` is empty. Both refs
  exist, and B (32657e9719) is an ancestor of the head.

## Findings

### M1 (MEDIUM): the per-draw diag dump overwrites the pending batch's staging

`hw/xbox/nv2a/pgraph/vk/renderer.c:1611-1618` (`diag_download_surface`,
`renderer.c:580-597`).

A diag session's per-draw dump calls `pgraph_vk_finish(SURFACE_DOWN)` and
then `diag_download_surface(d, pg, r->color_binding)`. That function copies
the colour binding into `BUFFER_STAGING_DST` at `bufferOffset = 0`. It does
not call `pgraph_vk_download_surface_complete_deferred` first.

The finish completes staged downloads only when
`deferred_downloads_frame == r->current_frame` (vk/draw.c:3656, 3724). The
flip's batch was submitted in an earlier frame slot, so it survives this
finish.

**Before this PR the case could not arise.** Every `surface_update`
completed a pending pre-download (the gate returned false on
`display_predownload_pending`), and every draw is preceded by an update. So
at any per-draw dump the batch was empty.

**Now it is the normal case.** The batch is pending at every draw between
the flip and its first consumer.

Failure scenario:

1. A diag session is running. Frame N's flip pre-records the display surface
   D at staging offset 0.
2. Draw k of frame N+1 hits the per-draw dump. `diag_download_surface`
   writes the colour binding C's pixels over offset 0.
3. The batch later completes, at the next record, the scanout request or the
   next pre-record. It copies C's pixels (C's row length) into D's VRAM and
   retires D at the captured generation. If D was not drawn since the flip,
   D is marked clean over VRAM that holds C's image.

The guest's CPU readback, the scanout, and the session's own
`frame_%d_display.ppm` then show an image the guest never drew. That falls
inside the investigation the diag session exists to serve. Blast radius:
diag sessions only.

Fix: call `pgraph_vk_download_surface_complete_deferred(d)` at the top of
`diag_download_surface`, or before its per-draw call site. The fix belongs in
this PR because this PR is what makes a batch outlive a draw.

### L1 (LOW): perflog `g_upw_map` / `g_upw_clr` key on raw binding pointers

`surface.c` `upw_set` / `upw_clear_read`. A binding freed with
`upload_pending` still set leaves its map entry. A later binding at the same
address inherits it unless `update_surface_part` sets it on creation, which
it does today. `g_upw_clr[]` compares by identity with the next update's
bindings, so a freed binding whose address is reused by the next bound
binding is counted in `clrfull`.

Failure scenario: a miscounted `why=` or `clrfull` in a perflog run. No
effect on rendering. Diagnostics only.

### L2 (LOW): the registered B arm is not the head's tree

B is 32657e9719. The head has since merged origin/master (0e938db24f) and
added the `clr/clrfull` probe. `git diff 32657e9719 HEAD -- hw/` shows 343
lines across renderer.c, surface.c and texture.c. Those lines come from
master folds and perflog-only counters, not from a change to the deferral.
Even so, the arms and goldens verdicts in NOTES 30-31 describe B, not the
head.

Failure scenario: a master change that interacts with the deferral, such as
#516's sysmem work, would not show in those verdicts. The fold's CI plus the
must-not-move guard re-run on the folded head is the check.
