# Audit pass 1 -- PR #317 lane/fmv303 (#303 Spikeout FMV green blocks)

Head audited: `2cf2301240`. Diff read: `git diff origin/master...HEAD`
(`display.c` +244, `green_cells.py`, `guest_tint.py`, `NOTES.md`,
`nv2a_index.json`).

**Result: no HIGH, no MEDIUM, three LOW.** The only emulator change is an
env-gated diagnostic probe (`HAKUX_FMV303_PROBE=1`); with the variable unset
it costs one `getenv` on the first displayed frame and a static-int test on
every frame after, and touches no rendering state, so "Prediction: none" is
consistent with the diff.

## What was checked and holds

- **Bounds of every guest-memory read.** PVIDEO: `len = pitch*h`, checked
  `addr < vram_size && len <= vram_size - addr`; the linear block walk also
  checks `o + 8*bpp > len`. Texture stages: `len` is `pitch*h` (linear) or
  `(size_t)w*h*bpp` (swizzled, cast before the multiply), and the stage is
  skipped as `unreadable` on `bpp == 0`, `dim != 2`, `offset >= dma_len`,
  `len == 0` or `len > vram_size - addr`. `fmv303_tint` is only called for
  A8R8G8B8 with `w >= 256 && pitch >= w*4`, so its furthest read,
  `(h-1)*pitch + w*4 - 1`, is inside `pitch*h`.
- **Linear pitch of 0** gives `len == 0` and is refused, not divided by.
- **Log volume** is capped at 20,000 lines and throttled to a register
  signature change or every 30th frame.
- **Default-off inertness.** `fmv303_probe` returns before reading any
  register when `enabled == 0`; `frame` only advances when enabled.
- **Index regen.** The 18 new `nv2a_index.json` sites are the probe's
  register reads and the one A8R8G8B8 `REF`; provenance moves to the lane's
  merge commit `15b403df29`, which is what a regen on this branch writes.

## Findings

### LOW-1 -- the probe can abort, contrary to its header comment

`hw/xbox/nv2a/pgraph/vk/display.c:1473` says "nothing here asserts", but
`:1674` calls `nv_dma_map`, which asserts
`dma_obj_address < ramin size` (`nv_dma_load`) and
`dma.address < vram size` (`nv2a.c`).

Scenario: probe on; the guest re-points `SET_CONTEXT_DMA_A` at an object
whose masked address is >= 64 MiB (or leaves a stage's ENABLE bit set with
a stale DMA select) and no draw has consumed it yet. The render thread,
which reads these registers racily while the FIFO thread writes them, maps
it at the next displayed frame and aborts the process -- a crash the
unprobed binary would not have. Bounded to runs with the env var set, and
the draw path asserts on the same object the moment it is used, so LOW.
Fix if the probe is kept: read the DMA object with `nv_dma_load` and range-
check `address`/`limit` locally instead of calling `nv_dma_map`, or correct
the comment.

### LOW-2 -- a lane-local probe lands on master in a file the lane cleared

The lane's own conclusion (PR body, NOTES) is that `vk/display.c` is not
where the green is made. Folding keeps 244 lines of #303-specific
instrumentation in the display path permanently, and its `index` entries
(`display.c:1611`, `:1650`, `:1697`, ...) will read as live register
consumers to every later `nv2a_index` query. No failure scenario at
default; quality. Consider keeping the probe on the lane branch only, or
say in NOTES that it is meant to stay for the tier1-off A/B in section 5.

### LOW-3 -- tint/lit ratio can exceed 1 in `guest_tint.py`

`docs/lanes/fmv303/guest_tint.py:22` divides `tint mb` by `lit` mb, but the
tint predicate (`G >= 40`) admits pixels the lit predicate (`R+G+B > 60`)
rejects. Scenario: a frame with 100 lit macroblocks plus 150 dim-green ones
at (0,50,0) scores 1.5, inflating `mean` and the `>0.9` count. The same
holds for `green_cells.py`'s green/lit pair if read as a ratio. The
reported runs (`rgb=0,118,0`, 920/920) are not in that regime, so the
lane's conclusion does not move; LOW.
