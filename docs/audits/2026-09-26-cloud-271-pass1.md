# Audit pass 1: PR #405, lane.cloud-271 (#271 X1A7R8G8B8 read side)

Head audited: `ef92658856` (lane/cloud-271). Diff read: `git diff origin/master...HEAD`
with origin/master at `bcdc649566`. The code is `psh.c`, `psh.h` and `vk/texture.c`.
The rest is the prediction file, lane notes and tools, and the regenerated nv2a
index. The measured `b_ref` `81e74b9ac9` is an ancestor of the head. The only
`hw/` commits after it are master's, merged in (#284/#315 psh work), so the arm
measured this diff's code.

Result: **no HIGH, no MEDIUM, 3 LOW.** Next label: `needs-audit-2`.

## What was checked and holds

- **Ordering against the uniform upload.** `pgraph_glsl_set_texture_x1a7_readback`
  is written in `create_texture()` and in the disabled-slot branch of
  `pgraph_vk_bind_textures()`. `pgraph_glsl_set_psh_uniform_values` reads it.
  Every path in `vk/draw.c` that binds textures calls `pgraph_vk_update_shader_uniforms`
  after the bind (full path `draw.c:2102`→`2120/2123`, MFP `4137`→`4158`, and
  the early-hit path `2093`). The one exception is LOW-1.
- **Where the setter sits in `create_texture()`.** It is after the only early
  return (`texture.c:1926`, LRU exhausted) and before the cache-hit/miss split.
  So a cache hit sets the stage's mode as well as a miss. After the early
  return the slot stays dirty and keeps its old binding, and the old mode goes
  with it, so the two cannot disagree.
- **Clean slots.** `bind_textures` skips `create_texture` for a clean slot and
  leaves the mode as the last bind set it. That is the same binding, so it is
  consistent.
- **The gate.** `surface_is_texture_source` (extent, levels, guest stride),
  `!upload_pending`, and a texture format whose view reads alpha from memory.
  The last condition keeps X8R8G8B8 views (alpha swizzled to ONE, used by the
  `XA_*_Add_SrcA_1-SrcA` captures) out. A 2-byte texture cannot pass the stride
  test against a 4-byte X1A7 surface.
- **The arithmetic.** `(mode-1)*128 + floor(round(a*255)/2)` gives `h>>1` for
  `_Z` and `0x80|(h>>1)` for `_O`, which is the truncation rule in
  `vk/constants.h`'s X1A7 entry. The transform sits before alphakill, after the
  signed-channel conversion. An X1A7 surface is a 4-byte ARGB8 texel, so the
  bytes16 path cannot reach it.
- **Uniform plumbing.** `texX1A7` is `int[4]`. The DECL table already carries
  scalar arrays (`texScale float[4]`, `colorKey uint[4]`) through
  `apply_uniform_updates`, and it is populated only when `locs[] != -1`.
- **Measured.** The `[job.arms]` verdict (`724d32f0280d`, 12:34 PDT) fails 1 of
  36 checks, and that one is the leg registered to fail
  (`Fmt_X1A7R8G8B8_O1A7R8G8B8` 16,383 → 118,083). The declared bound was "at
  least 58,754" higher and the measured rise is 101,700. The four Blend_surface
  rows reach 16,384, the Clear pair reaches 0, and all 26 must-not-move rows hold.
  The regression is recorded as accepted on #271 (`regression-accepted:271`).
  This audit does not re-open that decision.

## LOW-1: the SFP's push-descriptor bind can move `texX1A7` without a uniform upload

`draw.c:3952`: with push descriptors, the super-fast path calls
`pgraph_vk_bind_textures` when `texture_state_gen` moved. It can then `return`
at `draw.c:4076-4081` without calling `pgraph_vk_update_shader_uniforms`. The
X1A7 mode is the first per-stage uniform that `bind_textures` writes, so
until now nothing in this bind needed a uniform refresh.

**Failure scenario.** A stage is rebound from an ordinary ARGB8 texture to an
X1A7 surface of the same extent (or the reverse). The rebind moves
`texture_state_gen`, but `any_reg_gen` and `non_dynamic_reg_gen` stay where
they were, so the SFP's later checks keep `sfp_ok`. The draw then samples the
new texture under the previous draw's `texX1A7`: the alpha is transformed on a
plain texture, or left raw on the X1A7 surface. I could not name a register
sequence that moves the texture gen without moving `any_reg_gen`, so this is
not reachable as far as I can show, and it is LOW. The fix is one line: in that
branch, set `sfp_ok = false` when a stage's mode changed, or call
`pgraph_vk_update_shader_uniforms`.

## LOW-2: the rule is not idempotent, and it is applied whichever way the image was filled

The gate is `surface_is_texture_source`, not `surface_to_texture`. The mode is
therefore applied whether the texture image came from the surface's host image
or from a VRAM upload. That is correct on this head only because the download
writes the host `h` into VRAM unchanged (`constants.h:600-635`, "Not
implemented"), so both fills hold `h`. The write side is the next arm named in
the PR body. It will make VRAM hold the guest byte `(X<<7)|(h>>1)`. From then
on, a VRAM-path texture of that surface gets the rule a second time: on `_O`
the byte `0x80|a7` reads as `0x80|0x40|(a7>>1)`.

**Failure scenario** (latent, not on this head). The write side lands with no
change here. A title reads an X1A7 `_O` target through the VRAM path, for
example after the surface is evicted and re-uploaded, and gets alpha ≈ 0.75
where it should get ≈ 1.0. Record the constraint where the write side will
read it: in the `texture.c` comment, or in NOTES as the write-side lane's
first item. Also, the `constants.h` X1A7 comment ("Not implemented: this needs
the stored alpha requantised") is now half out of date, because the read side
is implemented.

## LOW-3: GL uploads a value only VK writes

`g_tex_x1a7_readback` is a file-static in `psh.c`, shared by both renderers.
GL reads it (`gl/shaders.c:968` → `pgraph_glsl_set_psh_uniform_values`) and
never writes it. The comment in `psh.h` says GL "stages 0". That is true only
if VK never ran in the process.

**Failure scenario.** A desktop build is switched live from Vulkan to OpenGL
(`pgraph.c` renderer switch, `g_config.display.renderer` changed at runtime)
while a stage's last VK bind was an X1A7 surface. Every GL draw on that stage
from then on halves the texel alpha, and on `_O` it also sets bit 7. Android
picks the renderer once at startup (`xemu_android.cpp:1309-1317`), and the
init-time fallback runs before any bind, so the shipping target cannot reach
this. The fix is to zero the array when a renderer is initialised, or to have
GL's bind path write 0.

## Not findings

- `psh.h` points at `docs/lanes/x1a7271/` for the derivation. That directory
  exists on master (an earlier lane), so the reference resolves.
- The `if (texX1A7[i] != 0)` block is emitted into every shader with a sampler.
  Its cost is one branch on a uniform per stage, which is dynamically uniform.
