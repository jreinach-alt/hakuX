## What was checked

1. **The flag's new value (2.0) is read only by `append_fog_factor`.**
   `git grep vtxFogSpecial` finds one reader (psh.c) and the writers
   (vsh.c, geom.c pass-throughs). The linear modes and the m != 0 exp
   draws test `vtxFogSpecial > 0.5`, which 2.0 satisfies, so an INF
   coordinate behaves as before everywhere except the new exemption.
2. **Interpolation cannot produce intermediate flag values.**
   `vtxFogSpecial` is declared `flat` in every shade mode
   (`glsl/common.c:61`), and every geometry path copies it from a
   single vertex (`geom.c:213`, `:723`, `:836`). So widening the range
   from {0, 1} to {0, 1, 2} cannot shift a 0.5 threshold across a
   triangle, which it would if the varying were smooth.
3. **The fixed-function path runs through the same block.** `vsh-ff.c`
   only defines `fogDistance`; the NaN/INF split at `vsh.c:958` handles
   both the FF and programmable paths.
4. **The exempt formula's inputs.** With the flag at 2.0 the vertex
   shader writes `oFog = 0`, and `fogCoord * fogParam.y` is 0 when
   `fogParam.y == 0` for any finite interpolated `fogCoord`. A
   non-provoking vertex with INF or NaN writes 0 too. So
   `fogX = bias - 1.5` as the comment says. `-0.0 == 0.0` holds in
   GLSL, so a negative-zero multiplier is exempt as well.
5. **NaN stays special in all modes.** The `isnan` branch is tested
   first, and `isnan(fogFactor)` is still OR-ed outside the exemption.
6. **Shader cache.** The psh text depends only on `fog_mode`, which is
   already part of the key. `fogParam.y` is a uniform and is tested at
   runtime, so no key change is needed.
7. **Prediction integrity.** `a_ref 6550967a5e` is `eb6ce3a908`'s base.
   `b_ref` is an ancestor of the head. The `[job.arms]` verdict on the PR
   is PASS on the registered file (sha256 `0674277564b0`). CI is green
   and the PR is mergeable. `origin/master` has moved since the lane's
   master merge, but none of those commits touch the fog lines in vsh.c
   or psh.c.

## Findings

### LOW-1: the header comment says the exp result at m = 0 is 0

`psh.c:1877-1878`: "except an infinite coordinate at m = 0 in the exp
modes, which is 0 (#278, below)". Read as a sentence, this says the
*factor* is 0. The code, the comment at `psh.c:1931`, and the goldens
all say the ordinary formula runs on x = bias - 1.5. For exp at
bias 1.5 that gives f = 1, not 0. It is the coordinate (0 * INF) that
is 0.

Failure scenario: a later edit trusts the header and folds the
exemption into `special = "0.0"` for m = 0. That breaks every
INF-FogExc-exp-* capture whose bias is not far below 1.5. Nothing
executes the comment, so this is LOW.

Suggested wording: "except an infinite coordinate at m = 0 in the exp
modes, where 0 * INF = 0 and the ordinary formula runs (#278, below)."
