# Audit pass 1 -- PR #402, lane.vshcpu345 (#345 half 2)

Head audited: `e956f40295`. Diff read: `origin/master...origin/lane/vshcpu345`
(10 files). Shipped code is `subprojects/packagefiles/nv2a_vsh_cpu/0001-silicon-arithmetic.patch`,
the wrap's `diff_files` line and the Android CMake staging block; everything under
`docs/lanes/vshcpu345/` is lane tooling and the prediction file is an arm.

**Verdict: no HIGH, no MEDIUM. Three LOWs.** Next state: `needs-audit-2`.

## What was checked and holds

- **Patch against the pinned source.** Read upstream `nv2a_vsh_cpu.c` at the
  wrap/CMake pin `1115255708`. Every hunk's context matches; CI built it and
  the device runs in NOTES (Thor SPECIAL_raw 22/44 -> 44/44) show the patched
  evaluator is what shipped.
- **MUL/MAD.** `zero_forced_mult` returns +0 when either operand compares equal
  to 0, so 0 x inf, 0 x NaN and -0 x 5 give +0; NaN x 5 still reaches
  `fix_inf_mult` and stays NaN. MAD adds c after the forced product, so
  `-0 x 5 + -0` is now `+0` (was `-0`); that is the stated MUL/MAD change.
- **DP3/DPH/DP4.** The forced sum is taken only when the plain sum is NaN, so
  no non-NaN result can change. A NaN that does not come from a 0 x inf/NaN
  term (inf + -inf, a NaN operand times non-zero, NaN in DPH's src1.w) is still
  NaN after the forced sum, then passes `fix_inf` unchanged -- same as before.
- **RCC.** Old code sent `result == +0` (RCC(+inf)) to the negative branch and
  returned -5.42101e-20; `signbit` fixes that. The old upper threshold
  `1.884467e+019f` is larger than 2^64 (1.8446744e19), so (2^64, 1.884467e19]
  escaped the clamp; it now compares against `kRCCMaxInt` itself. RCC(+-0) =
  1/+-0 = +-inf still clamps to +-2^64. NaN input returns before the division.
- **RCP/RSQ.** NaN input to RCP short-circuits to 0x7FFFFFFF. RSQ takes
  `fabsf(inputs[0])`, so a NaN input reaches `1/sqrtf(NaN)` and is
  canonicalised by `fix_ilu_nan`; finite and inf inputs are unchanged.
- **CMake staging.** `cmake_minimum_required(3.30)` covers `file(COPY_FILE)`
  (3.21). `GIT_CEILING_DIRECTORIES=${CMAKE_BINARY_DIR}` stops `git apply` from
  discovering the hakuX repo above the stage dir, and the marker re-check after
  apply turns the silent "skipped, rc 0" case into `FATAL_ERROR`. A pin bump that
  breaks the patch fails loudly at configure time. The patch is a configure
  dependency, so editing it reconfigures.
- **Wrap.** `diff_files=nv2a_vsh_cpu/0001-silicon-arithmetic.patch` resolves
  under `subprojects/packagefiles/`; the leading `From:`/`Subject:` lines are
  ignored by both `git apply` and `patch -p1`.
- **Prediction.** `b_ref a3baa35286` is the evaluator commit and an ancestor of
  the head (no rebase since registration); every leg is must-not-move with a
  stated mover, and GeometrySuperscreen is excluded with its reason.
- PR is MERGEABLE against master, `build` green.

## Findings

### L1 (LOW) -- DST's multiply is not zero-forced

`nv2a_vsh_cpu_dst` still computes `out[1] = fix_inf_mult(src0.y, src1.y)`. If
DST uses the same multiplier as MUL on silicon, DST with src0.y = 0 and
src1.y = inf gives NaN here where MUL now gives +0. There is no console row for
DST x 0 x inf in the SPECIAL_RAW set, so this is an unmeasured inconsistency,
not a demonstrated wrong value. Either apply `zero_forced_mult` there with a
row that measures it, or note in the patch header that DST was left alone
on purpose.

### L2 (LOW) -- edits to a local checkout no longer reach an incremental build

Before this PR, with `${REPO_ROOT}/subprojects/nv2a_vsh_cpu/src/nv2a_vsh_cpu.c`
present, the build compiled that file in place, so an edit to it was rebuilt
by the next gradle build. Now the file is copied at configure time, and only
the patch is in `CMAKE_CONFIGURE_DEPENDS`. Scenario: a lane edits the local
checkout to try an evaluator change, runs an incremental build; CMake does not
re-run, `nv2a_vsh_cpu-patched/src` keeps the old copy, and the APK carries the
old evaluator with nothing to say so. CI and fresh `.cxx` trees are unaffected,
and the supported way to change the evaluator is now the patch file. Fix: add
`${NV2A_VSH_CPU_SRC}/src/*` (the globbed list) to `CMAKE_CONFIGURE_DEPENDS`.
Relatedly, a file removed from the source is never removed from the patched
copy (harmless while the four sources are named explicitly).

### L3 (LOW) -- the marker accepts any revision of the patch

`string(FIND ... "hakuX #345")` treats any checkout carrying the marker as
patched. Once `0001-silicon-arithmetic.patch` is revised, a local checkout meson
patched with the earlier revision (and meson reapplies only on
`subprojects update --reset`, per the wrap comment) is copied as is, and the
Android build silently uses the old arithmetic. Needs a future patch revision
and a meson-patched local checkout, and the desktop build is unmaintained, so
bounded. Fix: embed a revision tag in the marker (e.g. `hakuX #345 r1`) and
match that exact string, or always stage from pristine source.
