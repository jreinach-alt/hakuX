## What was checked

- **Register plumbing** (`pgraph.c:4873-4877`, `nv2a_regs.h`). Bit 0 of
  `NV_PGRAPH_ZCOMPRESSOCCLUDE` is written from `GET_MASK(parameter, 0xF) != 0`
  before the existing ZCLAMP_EN switch. It is a separate `PG_SET_MASK`, so it
  does not disturb ZCLAMP_EN (bit 4). No other reader tests the whole register
  for equality: its other appearances in `pgraph.c:118` and
  `glsl/shaders.c:103` are only register-list entries. The method field
  `0x0000000F` matches the width of the neighbouring `ZCLAMP_EN` field
  (`0x000000F0`).
- **Shader key** (`psh.h:112`, `psh.c:312`). `ShaderState` is zeroed
  (`glsl/shaders.c:79`). `PshState` is hashed and compared as a whole struct
  (`glsl/shaders.c:40`, `:69`), and VK hashes `key->psh` the same way. So the
  new `bool` is part of the key, and a program built with the bit clear cannot
  be served for a draw with it set. The value is `reg & 1`, which is 0 or 1.
- **Operands exist on every path.** `vtxPos0..2` are declared on every
  fragment shader (`common.c:66-68`) and `clipRange` is a uniform. There are
  three cases:
  - Triangles go through the geometry shader, which sets
    `vtxPos{0,1,2} = pz[0..2]`, the triangle's three vertices.
  - Lines set the third vertex's z from vertex 0 (`geom.c:1062`), so the test
    reduces to "both endpoints out on one side".
  - Points have no geometry shader: `pgraph_glsl_need_geom` is false for
    anything but LINES and TRIANGLES after `prim_rewrite`, and the vertex
    shader sets all three to the one vertex (`vsh.c:970-972`). That is the
    correct single-vertex test.
- **Units.** The z-buffer ZCULL clip already compares values interpolated from
  `vtxPos*.z` with `clipRange.z/.w` (`psh.c:2906-2910`), so a raw `vtxPos.z`
  is in the same units. On the w-buffer path `vtxPos.z` is still screen z (the
  w-buffer code reads `.w`). The four `*_WBuf_*` movers landing on their exact
  figures confirm this on device.
- **Gate** (`psh.c:2601-2602`). When `cull_near_far` is clear, nothing is
  emitted, so every shader that does not set the bit has byte-identical text.
  The block is also skipped for z-buffer ZCULL, which the must-not-move rows
  `*_NEARFAR_ZCULL` (z-buffered) confirm.
- **Arm.** `1790404180-arms-cullnf276-{base,fix}` on nova: 868 captures each,
  no `unreadable`, and PARTIAL COVERAGE identical in both arms. The eight exact
  legs landed exactly. The four prose-band captures landed at 7,181, inside
  `<= 7,189`. The count was better 12, worse 0.

## Findings

### LOW 1: the "per-pixel clip already covers it" premise holds on Vulkan only

`psh.c:2597-2602`. The comment says the z-buffer ZCLAMP_EN_CULL case needs
nothing because "the per-pixel clip below already discards every pixel of
such a primitive". That clip is emitted only inside `depth_needed`, and
`depth_needed` is set only off-GL (`psh.c:317-322`). The GL renderer also
always runs with `GL_DEPTH_CLAMP` enabled (`gl/draw.c:585`).

Failure scenario: on the GL renderer, a z-buffered draw with
NEARFAR|ZCLAMP_CULL and a triangle wholly beyond CLIP_MAX is neither rejected
by this block (the gate excludes it) nor clipped per pixel, so it draws.

This is not a regression. The same draw drew before this PR, and GL already
ignored ZCULL. The goldens run on Vulkan. The fix would be
`!(depth_clipping && depth_needed) || z_perspective`, or a one-line correction
to the comment.

### LOW 2: wireframe triangles are tested per edge, not per triangle

`geom.c:497-499`, `:1059-1062`. With `POLY_MODE_LINE` on triangles, the
geometry shader emits each edge through `emit_line`. Each edge carries only
its own two endpoints in `vtxPos0..2`, with the third z copied from the first.

Failure scenario: take a wireframe triangle with two vertices below CLIP_MIN
and the third inside, drawn with NEARFAR|ZCLAMP_CLAMP. The new discard drops
the edge between the two outside vertices. The lane's own model
("rejects a primitive whose vertices ... are all below CLIP_MIN") keeps the
triangle, so silicon would draw that edge clamped.

No golden draws wireframe with NEARFAR, so which is right is unmeasured. It
needs a hardware capture before it becomes a defect. Record it in the NOTES
as unmodelled, next to CULL_IGNORE_W.

### LOW 3: the whole-primitive test ignores polygon offset, and is only as right as that choice

`psh.c:2604-2610` compares the raw vertex z. The z-buffer ZCULL per-pixel clip
compares `zvalue`, which includes `depthOffset + depthFactor*triMZ`
(`psh.c:2900-2901`).

Failure scenario: take a w-buffered or ZCLAMP_CLAMP triangle whose vertices
sit just below CLIP_MIN, with a positive polygon offset that would lift it
inside. The new block rejects the triangle, because it tests pre-offset z.
Whether silicon's near/far reject reads z before or after the offset is not
established by any golden (ZMinMaxControl draws no offset).

The same unknown also decides whether skipping the block on z-buffer ZCULL is
exact. There, the per-pixel clip reads post-offset z, so a z-buffer ZCULL
triangle that is all-out on raw z but lifted inside by the offset keeps its
pixels in the emulator. So the two branches assume opposite answers: the new
block assumes pre-offset z, and the skipped branch assumes post-offset z. Name the assumption in the comment or the
NOTES so a future offset golden can decide it.
