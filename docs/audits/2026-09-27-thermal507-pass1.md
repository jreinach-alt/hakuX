## M1 (MEDIUM): a window with no readable sample reads as clean

`thermal_state.py` says "a missing sample must widen a pause's bounds, never
read as clean", and the PR body says "a failed read does not count as
clean". `episodes()` drops every unread sample (`paused() is None`), so a
window that no readable sample covers produces no episode. Then
`in_window()` returns `[]`. `title_verdict.py` sets `measured=True` as long as
one sample anywhere was read, and scores the fps.

Reproduced with `--window FILE 60 240`:

- **Tail gap.** A clean `start` sample, then every `hold` sample and the `end`
  sample are `error` (10 lines). Output: `no pause may overlap +60..+240 s`,
  exit 1. Summary: `no thermal-pause device above 0; 11 samples, 10 unread`.
- **Interior gap.** Clean at +0, nine failed samples, clean at +300.
  Output: the same `no pause may overlap`, exit 1.

**Failure scenario.** The Thor pauses at +150 s. From there to the end, every
`adb shell` fails. This is the WSL `UtilAcceptVsock` case, which fails new
adb connections while the running `adb logcat` stream keeps flowing, so the
perf lines still arrive. The `end` sample fails too. Result: thermal.jsonl
has one clean reading before `am start` and nothing after it. The verdict
records `thermal.measured: true, in_window: false` and scores an fps that
includes the 5-7x paused segment. That wrong number goes into the 0.5 table,
which is what #507 set out to stop. The interior-gap case can also happen,
but a pause usually clears only after an 8 C fall, so the tail-gap case is
the likely one.

**Fix direction** (the lane chooses): give the window a coverage test. If no
readable sample falls at or after `end_t`, or if two readable samples inside
`mark_t..end_t` are further apart than a stated multiple of
`THERMAL_EVERY_S`, the window is unread. Then either void it
(`thermal-unread: ...`) or record `thermal.window_covered: false` and say in
the docstring which of the two is chosen. Add a selftest leg for each gap
shape. The current `all-fail` leg only covers a file with no readable
sample at all.

## L1 (LOW): a pause device whose `cur_state` read fails is dropped silently

`SAMPLE_SH` prints `cd N $(cat cur_state) $(cat max_state) type`. If the
`cur_state` read fails, the field is empty and the line becomes
`cd 12  1 thermal-pause-F8`. The `cd (\d+) (-?\d+) (-?\d+)` regex does not
match it, so that device is missing from `cool`. The other devices still
parse, so `paused()` returns False: a clean reading. No run has shown a
failed `cur_state` read yet. Suggested fix: when a `thermal-pause*`/`pause-cpu*`
line fails the regex, make the sample unread.

## L2 (LOW): device-time bounds are truncated to the second, and taken before the reads

`dev_time` is `date +%H:%M:%S`, printed before the sysfs loop runs, while
`mark_t`/`end_t` are logcat stamps in milliseconds. A clean sample taken at
x.9 s is recorded as x.0. As a `before` bound, that moves the end of the
pause span up to about 1 s earlier. A pause that clears less than a second
after `mark gameplay` can therefore miss the window. The effect is under a
second and the error is not on the conservative side. `date +%s.%N`, or
printing the clock after the loop as well, would close it.

## L3 (LOW): a hung sample stalls the hold loop for up to 30 s

`thermal_sample` runs inside the hold loop with `adb_shell(timeout=30)`. If
adb hangs, the foreground-flag check and the liveness probe run up to 30 s
late on each sample tick. The wall-clock deadline still bounds the run, so
the effect is a later abort, not a wrong one.

## L4 (LOW): `2>/dev/null` hides a sampler crash

`python3 thermal_state.py ... >>thermal.jsonl 2>/dev/null` writes no line
if the script dies with a traceback. The gap then disappears and, under M1,
reads as clean. The M1 coverage test covers this case too. Separately,
sending stderr to run.log would let a reader see the crash.

## Checked, no finding

- `dev_ts()` and `title_verdict.ts()` both parse `2000-MM-DD` in host local
  time, so the device-time comparisons match. The logcat and `date` stamps
  come from the same device clock.
- `overlaps()` with open ends (`after`/`before` None) is correct. A pause seen
  in the `start` sample runs to -inf and voids.
- In `title_verdict.py`, the `describe(..., min(read))` fallback is only
  evaluated when `eps` is non-empty, and that implies `read` is non-empty. An
  earlier `void` keeps its own reason, and thermal only fills an empty one.
  The void path already nulls the fps windows (line 341) and turns the first
  failure into `void: thermal-pause`.
- soak_title.sh under `set -u`: `THERMAL_OUT` is always assigned, the
  `[ -n ... ] &&` lines are not the script's last status, and a missing
  `thermal_state.py` in an old snapshot disables sampling once, with a
  message.
- The dispatcher runs soak_title.sh with `CAPTURE_LOG=$rdir/logcat.txt`, so
  thermal.jsonl lands in the rdir that title_verdict.py reads. The `$r`
  repetition paths are run_disc.sh, not soak_title.sh, so no two reps
  overwrite one thermal.jsonl.
- `thermal_state.py` is in both `SCRIPT_DEPS` and `snapshot_scripts`.
