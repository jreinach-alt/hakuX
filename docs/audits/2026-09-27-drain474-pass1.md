# Audit pass 1 -- PR #517 lane.drain474 (#474, drain before a surface-to-texture bind only when it copies)

Head audited: `7b1aea3abc` (`lane/drain474`), diffed against its merge base
with master. The C diff is one commit, `73a4126325`, in
`hw/xbox/nv2a/pgraph/vk/texture.c` (`create_texture`, the cache-hit
surface-to-texture rebind). I also read `docs/lanes/drain474/NOTES.md` and
the three prediction files. GitHub's file list also shows
`docs/lanes/slowdown462/*`. Those files came in with PR #512, which has
folded. The three-dot diff against `origin/master` does not contain them.

**Verdict: no HIGH, no MEDIUM, three LOW. The PR goes to `needs-audit-2`.**
None of the LOWs changes behaviour. Each needs a logged decision: fix it, or
say why not.

## The change

Before the change, the rebind (`surface->draw_time != snode->draw_time`) ran
`pgraph_vk_flush_all_frames` whenever the node might still be in flight
(`snode->submit_time + num_active_frames > submit_count`). It did this before
`can_direct_bind` was computed. The drain now runs, with the same condition,
only in the `else` branch, ahead of `copy_surface_to_texture`. The direct
branch runs `bind_surface_as_texture` or `bind_zeta_surface_as_texture` with
no drain.

## What was checked and holds

- **A direct bind writes nothing the drain protected.**
  - `bind_surface_as_texture` (`texture.c:1125`) and
    `bind_zeta_surface_as_texture` (`:1180`) record a barrier on
    `surface->image` only. The zeta variant also updates
    `surface->image_layout`. Both set `texture->draw_time`, a CPU field.
  - Neither touches `snode->image`, `snode->image_view` or the node's
    layout.
  - The drain waited for frames that may still sample the node's image.
    Only the copy writes that image, and the copy keeps the drain.
- **Descriptors of frames in flight.**
  - Push path (`shaders.c:580`, `draw.c:4096`, `:4283`): the image info is
    recorded into the command buffer. A later bind cannot change what a
    submitted frame reads.
  - Standard path: a new texture set is taken from the ring, and the ring
    wraps only through `pgraph_vk_finish` + `flush_all_frames` (`shaders.c:602`,
    `:706`).
  - Neither path rewrote a set because this drain ran. So removing the drain
    does not expose a set that a frame in flight still reads.
- **Queue ordering of the surface barrier.** `flush_all_frames`
  (`draw.c:3397`) waits only on frames that have been *submitted*. It never
  covered writes in the command buffer that is still recording, and those are
  the writes the direct-bind barrier orders against. For submitted work, the
  barrier's first scope already includes every earlier submission on the
  queue. The removed wait therefore did not supply ordering that the barrier
  lacks.
- **The copy branch's condition still reads a live `submit_time`.**
  `texture.c:2850` bumps `submit_time` on every bound node, including one
  bound directly. The bump is conservative: a later copy into a node that was
  only bound directly still drains when the node is recent. It never skips a
  drain it needs.
- **The same shape already exists.** The cache-miss bind (`texture.c:2793`)
  and the same-`draw_time` rebind (`:2354`) bind directly with no drain. After
  this change, the direct rebind behaves the same way those two paths do.
- **Side effects the drain had.** `flush_all_frames` also drains deferred
  texture and surface releases, resets per-frame staging offsets and, when no
  command buffer is recording, resets the descriptor rings (`draw.c:3444`).
  These still happen on the normal frame-fence path and on ring or buffer
  overflow. With fewer drains, deferred releases are retired later but
  still retired. A ring that fills up takes its own finish-and-drain path.
- **Evidence on device.**
  - Pixel arm: 363/363 score rows and captures are byte-identical A vs B on
    the seven suites that bind a surface as a texture.
  - Blinx and AUF soaks: `faf` falls to 0.00, `bs` is unchanged (+9% and 0%),
    and there are no validation, device-lost or crash lines. B's play shots
    show no stale, torn or black quads that A's do not.
  - The Blinx P1 leg failed as registered, and the PR reports that. NOTES
    explains the failure: the gfps line median weights the fast spans, and
    the time-weighted rate moved -1%. It is not re-read as a pass.

## Findings

### LOW-1 -- the pixel arm cannot show it reached the changed branch

`drain474-s2t-pixels.json` is the only arm with byte-level evidence. Its
build is not perflog, so nothing in it shows that any of the 363 rows went
through the cache-hit direct *rebind*, the path that changed, rather than
the cache-miss direct bind or the copy branch. NOTES states this limit
(§Results, "The limit of this arm"). The rebind is known to run only in the
two soaks, and there the check is by eye on a few shots per arm. Failure
scenario: a stale-descriptor or layout race that shows up only as a changed
texel region in a frame the shots did not sample would pass all three arms.
The code reading above says no such race exists. The measurements do not
test it. Suggested (optional): name one suite row that reaches the rebind,
for example from a perflog run of the suite showing `bs > 0` on a cache hit,
or record in NOTES that the correctness claim rests on the code reading.

### LOW-2 -- the Blinx registration names the Thor; both arms ran on the Nova

`drain474-blinx-soak.json` has `"device": "thor"`. Both arms ran on the Nova
(`ee317437`). NOTES and the PR body both say so, and the A/B stands because
the two arms share a device. The registered file still reads as a Thor
result to anyone who opens only the prediction. No behaviour depends on it.
Suggested: leave the registration as it is (its hash is cited) and keep the
note, or add a one-line `note` in a follow-up registration. Do not edit the
hashed file.

### LOW-3 -- the code comment carries a measured figure

The new comment in `create_texture` ends with "On AUF (Nova) it ran 0.27
times a flip at 16.6 ms each, every one of them ahead of a direct bind."
That is one soak's figure on one device and one ref. It goes stale the
first time the scene or the drain cost changes, and the code gives the
reader no way to notice. The reasoning above it, that only the copy writes
the node, is what the comment has to carry. Suggested: drop the figure or
point to `#474` / NOTES for it.

## Outside the diff (not a finding against this PR)

In the standard descriptor path (`shaders.c:697-715`), a hit in
`tex_desc_cache` stores the cached set's handle into
`descriptor_sets[descriptor_set_index]`. That overwrites the ring slot's own
handle. The miss path only clears the cache on its own overflow.
`flush_all_frames` resets `descriptor_set_index` and leaves the cache alone.
After a reset, a later miss at that index can call
`vkUpdateDescriptorSets` on a set that another cache entry still maps to
different views. The push path is used wherever push descriptors are
supported, so the standard path, and this problem with it, applies only
where they are not. This PR does not touch that code and reduces how often
the reset runs. It is recorded here for the board to route. It does not
gate this fold.
