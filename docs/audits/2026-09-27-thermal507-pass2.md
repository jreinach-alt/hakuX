## M1: a window with no readable sample reads as clean -- CANNOT OCCUR

Pass 1's two reproductions, rebuilt with the selftest's `tp_fix` and run
through `--window FILE 60 240`:

- Tail gap (clean at +0, ten failures): `unread: no reading at or after the
  window's end +240 s (last +0 s)`, exit 2. It was exit 1, `no pause may
  overlap`.
- Interior gap (clean at +0 and +300, nine failures between): `unread: no
  reading from +0 s to +300 s (300 s > 90 s)`, exit 2. It was exit 1.

The failure scenario was that the verdict scored an fps across the pause.
`judge()` now calls `coverage()` whenever the window is measured and no
episode hits it. A gap makes the run `void: thermal-unread: ...` and records
`thermal.window_covered: false`. The void goes through the same path as
`thermal-pause`, which nulls the fps windows. The selftest's verdict leg
checks this: a clean sample before the mark followed only by failures gives
void, no frame rate, and `window_covered` False. A single failed sample (a
60 s gap) is still covered. That is intended, and the `unread` leg pins it.

`coverage()` in detail: the tail check needs a readable sample at or after
`hi - 1 s`. The chain runs from the last reading at or before `lo` (or `lo`
itself), through every reading inside the window, to the first reading at or
after `hi`, and any link longer than 90 s is a gap. If no reading precedes
`lo`, the chain starts at `lo`. That case is only reachable when the `start`
sample (taken before `am start`) failed, and a first reading within 90 s of
the mark then counts as covered. A pause present at that first reading still
voids through the open-ended episode. A pause that begins and clears within
those first 90 s is the same bounded risk as any interval between two
samples, so this is not a finding.
