## What was checked, and held

- **State plumbing.** `pgraph_glsl_set_geom_state()` sets the two new fields
  after `primitive_mode` and `polygon_front_mode` are computed, and resets
  them to 0 on every call, so no draw inherits a previous draw's cull state.
  They are non-zero only for output `PRIM_TYPE_TRIANGLES` under
  `POLY_MODE_LINE` with CULLENABLE.  `pgraph_glsl_need_geom()` asserts
  front mode == back mode, so a LINE/FILL split cannot reach this code.
- **Shader key and rebinding.** Both fields live in `GeomState`, so they are
  part of the ShaderState hash.  `NV_PGRAPH_SETUPRASTER` is already in
  `pgraph_glsl_check_shader_state_dirty()`'s register list
  (`glsl/shaders.c:101`), so a guest that changes CULLCTRL or FRONTFACE
  between two line-mode draws gets a new shader.  ShaderState is
  memset to 0 before it is filled (`glsl/shaders.c:79`), so the new padding
  byte at the end of GeomState cannot split keys.
- **Persisted keys.** Vulkan: `SHADER_STATE_LAYOUT_VERSION` 4 -> 5 is
  correct either way, as the lane says.  GL: the on-disk binary cache is
  keyed by the ShaderState hash and rejected when the xemu version string
  differs (`gl/shaders.c`), so a stale GL entry cannot load a non-culling
  shader for the new key.
- **Generated GLSL.** `line_cull_body[512]` has function scope, so `body`
  still points at live storage when it is used further down.  The longest
  formatted body is about 320 bytes, and `check.sh` compiles all 32
  Vulkan/GL variants.  `kahan_det()` is present wherever `calc_triz()` is,
  and the old body already called `calc_triz()` unconditionally.  With
  CULLENABLE clear, or CULLCTRL = 0, the body is the old string verbatim.
- **Cull constants.** CULLCTRL FRONT=1, BACK=2, FRONT_AND_BACK=3
  (`nv2a_regs.h:536-538`) match the switch.  A NaN face culls nothing;
  FRONT_AND_BACK culls every finite face.
- **Double culling.** None.  The host rasterizer's cull (Vulkan when the
  draw is not widened, GL always) sees only the lines the GS emits, and
  lines are never culled, so the GS test is the only cull on this path.
- **Winding.** Strips and fans are rewritten to `PRIM_TYPE_TRIANGLES` under
  line mode (`prim_rewrite.c:60-62`).  Odd strip triangles are reflected,
  not rotated, so every triangle winds as the guest drew it.  The arm's
  bit-identical `Shade_model/ProgLM_TriStrip_*` guard is the evidence for
  this.  `v_vtxPos` is in guest screen space, so the face sign does not
  depend on the API's y convention.
- **Arm.** Registered legs (better = 12, worse = 0, must-not-move over
  Front_face FM, Shade_model ProgLM, Line_width, 3D_primitive lines) all
  hold per the lane's `ab_compare.py --expect` run on
  `1790435466-arms-cull13-*`.

## Findings

### L1 (LOW) -- the MUST MOVE bounds are prose, not machine legs

`cull13-linemode-cull.json` has `"expect": {}`.  The per-capture bounds
(FaB <= 20, the other eight <= 720) are in the prediction text only.
Failure scenario: a rerun where the four FaB rows stop at 500 px, not 0,
would still pass `--expect`, because they would still count as "better".
The lane's NOTES table shows the bounds held (0, 688, 689), so this is a
gap in the instrument, not a wrong result.

### L2 (LOW) -- the lane judged its own arm; the verdict is not on the head

No `[job.arms]` verdict was posted, so the lane ran `ab_compare.py` on the
two result dirs itself.  The arm also measured b_ref d750443b2a on base
02374a6847.  The head now also carries 34 master commits merged in
e404f3c16c, including #389's `vk/draw.c` SFP guard.  Failure scenario: an
interaction between the merged master code and this hunk would not appear
in the 12-better verdict.  The blast radius is bounded: the merge
conflicted only on the index, the hunk is GS-only, and CI builds the head.

### L3 (LOW) -- stale comment in `vk/draw.c`

The widened-draw cull clear still says "Silicon does not cull lines".  For
line-mode triangles, this hunk refutes that.  The lane records this in its
NOTES and leaves the file alone because it belongs to lane.remote.  The
code there stays correct; only the comment misleads the next reader.

### L4 (LOW, declared) -- QUADS / QUAD_STRIP / POLYGON under line mode are not culled

These reach geom.c as `PRIM_TYPE_LINES` and have lost their face by then.
Failure scenario: a guest that draws culled wireframe quads still sees the
culled faces' edges.  This is documented in the code comment and in NOTES
"Do not repeat", and no scored capture covers it today.  It is recorded
here so pass 2 does not read it as fixed.
