## M1: the failed Blinx must-not-regress leg would ship the range test by default

Pass 1's scenario: the PR folds, every title gets the range test, and Blinx
gameplay may be 7 gfps where it was 9. The remediation took remedy 2 (flip
the default). Traced on the head:

- `hakux_tcg424_range_on()` (tb-maint.c:781-791) now reads
  `HAKUX_TCG424_RANGE` and returns `e && e[0] == '1'`. Unset, empty, or any
  other value gives 0.
- The invalidation loop's discard predicate (tb-maint.c:1934) opens with
  `!hakux_tcg424_range_on() ||`. With the switch off, every block on the page
  is discarded, which is the fork's whole-page behaviour (xemu 703566ce33).
- The store fast path (tb-maint.c:2185) is
  `hakux_tcg424_range_on() && page_code_bitmap_misses(...)`, so with the
  switch off `page_code_bitmap_misses` is never called.
- `page_code_bitmap_misses` is the only caller that can create a bitmap
  (`page_code_bitmap_build` at :872 when `!p->code_bitmap`). The other build
  call (:2052) and `tb_page_add`'s `page_code_bitmap_add` (:1223) are both
  inside `if (p->code_bitmap)`. So with the switch off no bitmap exists, the
  per-page `code_writes` count never moves, and the rebuild pass after a
  walk (L4) never runs.

So a default build takes exactly master's invalidation path, plus one cached
flag read per armed store. The scenario needs the range test on by default,
and it is not. Shipping it by default now needs a later change, and NOTES.md
(section after line 205) says what that change must register first: a Blinx
leg read on gameplay, with at least 3 interleaved runs per arm.

## LOWs

- **L1 (cbb races): fixed by rewording.** The comment at tb-maint.c:83-91 now
  says builds of different pages can race and that `cbb` is a rate, not a
  check. That was one of the two remedies pass 1 offered.
- **L2 (duplicate declaration): fixed.** `hakux_tcg424_range_on()` is declared
  once, in `tb-internal.h` under `#ifdef XBOX`. Both `cputlb.c` and
  `tb-maint.c` include that header, and the per-file declarations are gone.
  CI `build` is green on the head.
- **L3 (bitmaps outliving code) and L4 (double list pass): unchanged.** Both
  need a bitmap, and with the default off no bitmap is built. They are still
  pricing notes for whoever flips the default.
