# Audit pass 1: PR #396, lane.blinx372d (#372 GPU handoff for incompatible evictions)

Head audited: `3acfacb0cd`. Auditor: job.cloud, 2026-09-26.

**Result: no HIGH, no MEDIUM, four LOW.** Next state: `needs-audit-2`.

## What the diff does

`hw/xbox/nv2a/pgraph/vk/surface.c` is the only code change. It adds two things.

- **Counter.** The `[evict372]` counter records which compatibility fields
  differ on each incompatible eviction in `update_surface_part`, and keeps a
  table of the eight most-repeated draw-dirty held -> target pairs. It prints
  every 5 s from `surface_watch_log_periodic`.
- **Handoff.** An incompatible eviction of a draw-dirty binding whose shelved
  partner at the same address has the same width, height, pitch, swizzle,
  bytes per pixel and size is recorded on the GPU with no deferred download:
  image -> `compute_dst` -> (pack if DS) -> (unpack if DS) -> image. The
  partner becomes the active binding, dirty, with a new draw generation. The
  evicted binding is shelved clean with `vram_newer`.

The rest of the diff is lane notes, `abread.py`, `cc_surface.py` and three
prediction files.

## What I checked, and how

1. **Byte equivalence with the VRAM round trip.** I compared the handoff with
   `download_surface_record_deferred` (DS: image -> `compute_dst` with the
   stencil region at `ROUND_UP(w*h*4, minStorageBufferOffsetAlignment)`, then
   pack into `compute_src`) and with `upload_surface` (DS: copy to
   `compute_dst`, unpack into `compute_src`, stencil region at the same rounded
   offset). The handoff uses the same regions, the same pack/unpack entry
   points with `downscale=false`, and scale factor 1 is required. Colour
   download and upload are raw copies (`no_conversion_necessary` is asserted on
   both sides), and `surface_stages_guest_bytes` excludes every case where
   `host_bytes_per_pixel != bytes_per_pixel`. Swizzle is required equal, so
   swizzle-then-unswizzle is the identity. The only thing VRAM would have added
   is pitch padding, which the upload never reads. D16 on either side is a
   non-DS raw copy of 2 bytes/px. The DS -> DS case copies `compute_src` ->
   `compute_dst` before the unpack, and the unpack reads `compute_dst`. Nothing
   aliases.
2. **Synchronisation.** `surface_handoff_barrier` is a global memory barrier
   over TRANSFER|COMPUTE read/write, issued before the first copy (this covers
   WAR against an earlier deferred DS download in the same command buffer that
   used the same compute buffers) and after every step. Attachment -> transfer
   hazards are covered by `pgraph_vk_transition_image_layout`. Every pair the
   handoff can request (src: DS_ATTACHMENT/GENERAL/TRANSFER_SRC -> TRANSFER_SRC
   and back; dst: UNDEFINED/TRANSFER_SRC/GENERAL/DS_ATTACHMENT -> TRANSFER_DST
   -> GENERAL or DS_ATTACHMENT) is in the helper's table (`image.c:72-309`), so
   nothing reaches its `assert(!"unsupported layout transition!")`. The colour
   restore layout is GENERAL, matching the download's `restore_layout`.
3. **Partner identity.** `surface_shelf_matches` is `get_shelved_surface`'s
   predicate field for field (`surface.c:2520-2525`). The held binding is
   rejected if it matches. `shelve_surface` only inserts at the head and prunes
   nothing, so the partner found before shelving is the first match after it.
   The fallback branch therefore only runs if the two predicates drift apart
   (see L3), and if it does, it records the skipped download and sets
   `shelf_stale`, because `surface_vram_written` cannot mark a binding that has
   already left the shelf. That is correct.
4. **Obligations and the #387 watch.** The partner is re-registered by
   `surface_put`, then `pgraph_vk_surface_watch_mark_dirty` sets `draw_dirty`.
   `draw_generation++` against a fresh target's `download_generation` makes
   `surface_access_callback`'s generation test fire. The evicted binding's
   watch removal and the partner's insert are both `async_safe_run_on_cpu`
   items, queued in that order. The callback takes `pgraph.lock`, and the pfifo
   thread holds that lock through the whole of `update_surface_part`. So a CPU
   access either hits the old watch after the partner is dirty (the callback
   walks `r->surfaces` and downloads the partner) or hits the new watch. There
   is no unwatched window. A later lookup that invalidates the range downloads
   the partner as an ordinary dirty active surface. Texture binds go through
   `pgraph_vk_download_surfaces_in_range_if_dirty`.
5. **Declines.** Declined without TCG, at scale != 1, if the held binding is
   clean, owes a CPU download, has a CPU write pending, or is the pending
   display pre-download. Also declined if another active binding overlaps, or
   if a dirty shelved binding at another address overlaps (the one
   `surface_put`'s `invalidate_overlapping_surfaces` would write back before a
   re-upload). A dirty shelved third binding at the same address is not
   declined, but master's round trip leaves it in the same state, so the
   handoff does not change that exposure.
6. **Ordering in `pgraph_vk_surface_update`.** In the upload path,
   `unbind_surface` already runs before `update_surface_part` on master, so the
   handoff's queue flush after `shelve_surface` has the same bound state as the
   old download's flush. The partner is `upload_pending = false`, so the
   `pgraph_vk_upload_surface_data` after `complete_deferred` is skipped. The
   partner's `draw_time` is set there, which keeps a later synchronous
   download's finish test correct for the handoff's commands.
7. **Counter.** `evict372_side` zeroes padding before the `memcmp`. `why` is
   masked to 7 bits. The mask string stops 48 bytes short of 512, and the
   longest entry is under 48. The periodic log reads the counters without
   `pgraph.lock`, which can only give a torn count in a log line.
8. **Evidence.** `blinx372d-mnm2.json` names five suites in `must_not_move`
   (not an empty `expect`), with A = master 9f5a3dfc98 and B = the merge
   790dc14730. The PR reports 102/102 byte-identical with nonzero B
   `handoffs=`, and the PR carries `verified`. The prediction names what would
   move each suite and counts white-content rows as unreadable, not as passes.
9. **Merge.** `git merge-tree` against `origin/master` (62 commits ahead of
   this head) is clean.

## Findings

### L1 (LOW): the title says the demo's two downloads are removed; they are not

The PR title is "remove the two synchronous surface downloads in the Blinx
demo". The body's own result table shows the demo A/B VOID with B
`handoffs=0`: the demo's pair is a 640x480 <-> 320x240 size flip, which the
hunk declines. A fold that takes the PR title as the commit subject would
record a performance fix that did not happen, and anyone later bisecting the
demo's frame rate would read this commit as the one that removed the waits.
**Fix:** retitle, for example "#372: GPU handoff for same-geometry
incompatible evictions (demo not covered)".

### L2 (LOW): the handoff's compute dispatches skip the descriptor-budget pre-check

`download_surface_to_buffer` and the deferred download check
`pgraph_vk_compute_needs_finish` before they pack. `surface_handoff_record`
issues one or two compute dispatches (pack and/or unpack) with no such check.
If the 4096-entry `compute.descriptor_sets` pool is exhausted mid-record,
`update_descriptor_sets` calls `pgraph_vk_flush_all_frames` and rewinds the
index to 0. That rewrites descriptor sets that earlier dispatches in the still
open current-frame command buffer may have bound. The upload path's unpack has
the same exposure on master, and reaching it needs about 4096 compute
dispatches between finishes. The handoff does not add a new class of hazard,
but it is a new caller in a per-frame path.
**Fix (optional):** check `pgraph_vk_compute_needs_finish(r)` in
`surface_handoff_partner` and decline when it is true.

### L3 (LOW): `surface_shelf_matches` copies `get_shelved_surface`'s predicate by hand

The handoff's correctness depends on the two agreeing. If they drift apart,
the result is still correct (the fallback takes the download), but every
eviction then pays a download plus a wasted handoff decision, and only the
`fallbacks=` count shows it. **Fix:** have `get_shelved_surface` call
`surface_shelf_matches`, so there is one predicate.

### L4 (LOW): the `mem_dirty` decline is dead in the only mode the handoff runs in

`update_surface_part` computes `mem_dirty` only when `!tcg_enabled()`
(`surface.c:4050`). `surface_handoff_partner` returns early without TCG. So
`mem_dirty` is always false whenever the test is reached, while the block
comment lists "wrote the range (upload_pending, mem_dirty)" as a guard. The
real guard for a CPU write is `held->upload_pending`, which the watch sets, so
behaviour is correct. **Fix:** drop the parameter, or say in the comment that
it only matters in a non-TCG build.

## Not findings

- The periodic `[evict372]` log adds up to nine lines every 5 s to the existing
  periodic block, unconditionally, including on release builds. That is the
  same policy as the `surf92`/watch lines next to it.
- `handoff_dst` is only compared by pointer after `get_shelved_surface`, and
  the handoff overwrites the whole image, so even a reused allocation at the
  same address would get complete pixels.

## For pass 2

There is no HIGH or MEDIUM scenario to re-verify. Pass 2 should check whether
L1-L4 were taken, and that any remediation commit re-registers the
must-not-move arm on its own head, since a rebase or merge un-ancestors the
registered `b_ref`.
