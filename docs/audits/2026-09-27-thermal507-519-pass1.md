# Audit pass 1: PR #519 (thermal507), the cool-down gate before MAX

(`2026-09-27-thermal507-pass1.md` is PR #508's pass 1. This file is #519's.)

PR head audited: `fdc65ca0f3`. Scope: the PR's four files
(`docs/testing/soak_title.sh`, `docs/testing/thermal_state.py`,
`docs/testing/jobs/selftest.d/99-thermal-pause.sh`,
`docs/lanes/thermal507/NOTES.md`).

**Result: no HIGH, no MEDIUM, four LOW.** The gate runs after the
force-stop and display check and before `arm_audio`/`perf_enter`, so it
waits with the title stopped and the device at its own modes. Every exit
from the loop is bounded: an unread sample, a missing zone or a missing
sampler ends it (not gated), and a hot device ends it at the cap. The
`start` sample, the hold samples and the verdict's mark-relative window are
unchanged. `--window` and `--summary` count from `start`, so the cool-down
samples do not shift the offsets the verdict reads. No dispatcher-side kill
is keyed to `seconds`. The only time limit is harness_health.py's overrun
line, which the 360 s cap was chosen to stay under.

The PR registers no prediction. That fits: this is a harness gate, and
selftest 99 covers it with a named failure world per leg.

## Findings

### L1 (LOW): a pause episode from the cool-down renders as `+-N s` in the THERMAL: line

`thermal_state.py` `origin()` now puts +0 at the `start` sample. `describe()`
formats `"+%.0f s" % (t - t0)`. For an episode whose `after`/`first` fall in
the `cool` samples (the gate gave up while paused, which is the documented
"starting hot" case), the negative offset prints as `began after +-60 s and
by +-40 s`. A pause that set and cleared during the cool-down (paused at
72 C, cleared at 70 C, waited on to 65 C) is also reported in run.log's
`THERMAL:` line as a pause, with `cleared by +-N s`, although it cannot
touch any scored window. The verdict is not affected: `in_window` uses the
mark, and such an episode does not overlap it. Only a reader of run.log is.
Fix: format the sign properly (`%+.0f`), and have the summary say when an
episode ended before `start`.

### L2 (LOW): the unwindowed verdict path still counts from the first sample

`title_verdict.py:315`: when there is no mark, `describe()` is given
`min(dev_ts(r) for r in read)`, which is now the first `cool` sample, not
`start`. The pauses listed in verdict.json then disagree by the length of
the cool-down with the `THERMAL:` line, which uses `origin()`. Fix: call
`thermal_state.origin(read)` there too.

### L3 (LOW): `waited <s> s` counts sleeps, not elapsed time

`cool_waited` adds `THERMAL_COOL_EVERY_S` per iteration. Each iteration also
makes one adb sample and two python3 starts. Over the vsock that is several
seconds. At the 360 s cap, with 18 iterations, the real wait can be a
minute longer than the logged `after 360 s`, and that minute counts against
harness_health.py's `seconds + 10 min` line. The cap was sized from that
line. Fix: measure with `$SECONDS` or `date +%s`.

### L4 (LOW): a sampler that writes no line leaves `--cool` reading the previous sample

`--cool` reads the last line of thermal.jsonl. If `thermal_state.py` raises
(a traceback to run.log, no line appended) on the second or a later
iteration, `--cool` reads the previous, hot sample again and the gate keeps
waiting on stale data. This is bounded by the cap, and it cannot start a run
early (a stale read is always the hot one that kept the loop going), so the
only cost is queue time. Fix: count lines before and after the sample, and
treat "no new line" as unread.

## Not findings

- The gate also runs under `PERF_REGIMEN=rest` and on the Nova, since it
  is keyed on the zone and not on the regimen. Waiting out 65 C before a
  REST run is conservative, not wrong. `THERMAL_COOL_C=off` exists.
- After KEYCODE_WAKEUP the screen stays lit during the wait. That adds a
  little heat, and the gate measures that heat, so the result is still
  honest.
- An adb failure mid-wait ends the gate (`not gated`), and the run starts
  possibly hot. The code comment says this is the intended trade ("must
  never cost the run"), and #508's void still judges the window.
