# Audit pass 2: PR #393, lane.pshaniso284 (#284 anisotropy probes, #315 BRDF)

Head verified: `4f6c7c9c38` (lane/pshaniso284), the remediation of pass 1
(`2026-09-26-pshaniso284-pass1.md`). CI on that head: build, build, check all
SUCCESS; the PR is mergeable.

Result: **clean.** The MEDIUM and LOW-2 scenarios can no longer occur. LOW-1 is
still open and is not a fold blocker. Next label: `fold-ready`.

## MEDIUM-1: the sampler dropped anisotropy for stages the shader does not probe. Cannot occur now.

`pgraph_glsl_tex_aniso_probes(pg, i)` (`psh.c:321`) is now the only place that
decides this. The shader (`state->tex_aniso[i]`, `psh.c:596`), the VK sampler
(`vk/texture.c:1782`) and the GL sampler (`gl/texture.c:695`) all call it. The
texture.c files no longer have their own BOX_LOD0 test. Both samplers set
`max_anisotropy = 1` only when the predicate returns more than 1.

I checked the predicate against each exclusion in the pass-1 scenario, and
against the emission site (`psh.c:3323-3340`):

| Pass-1 case | Predicate returns 1 because |
|---|---|
| cube map | `CUBEMAPENABLE` |
| 3D texture | `DIMENSIONALITY != 2` |
| shadow map / depth format (includes the VK `usampler2D` x8y24 case) | `pgraph_get_color_format_info(..).depth`, the same `f.depth` that sets `shadow_map[i]` (`psh.c:573`) |
| BUMPENVMAP, DPNDNT_*, DOT_*, any non-PROJECT2D mode | `mode != PS_TEXTUREMODES_PROJECT2D`, read from `SHADERPROG` |
| point-sampled Y16 / R16B16 | `tex_split_bytes16()`, which is now shared with `tex_bytes16[i]` and so cannot drift from it |
| convolution | MIN = `CONVOLUTION_2D_LOD0` is not `BOX_LOD0` |

The only other exits between the predicate and the probe loop are
`tex_unusable` (`get_sampler_type`, `psh.c:1336`) and a disabled or
undecodable stage. On the PROJECT2D path, `tex_unusable` is set only for a
non-2D shadow map, a 3D depth texture, or dim 1 or 4, and every one of those
already returns 1. A disabled or undecodable stage is bound to the dummy
texture and is never sampled. So in the other direction the predicate never
removes host anisotropy from a stage that does not take the probes.

The predicate now reads the stage mode, so it needs cache invalidation. That
is in place:

- `SET_SHADER_STAGE_PROGRAM` is out of the `method_fast` table. Both fast-path
  loops (`pgraph.c:764`, `pgraph.c:1815`) fall through to the slow path for an
  empty entry. The handler (`pgraph.c:4980`) marks `texture_dirty[i]` for
  every stage whose 5-bit mode changed. `pgraph.c:4992` is the only writer of
  `NV_PGRAPH_SHADERPROG`.
- The VK register-cache shortcut (`vk/texture.c:2702-2723`) compares
  `TEXFMT`, `TEXCTL0`, `TEXFILTER` and the stage's `SHADERPROG` bits. Those
  are every register the predicate reads, so a dirty slot cannot be skipped
  with a stale anisotropy. `max_anisotropy` is in `TextureKey`, so the two
  samplers are separate cache nodes.
- GL reapplies parameters only for dirty slots (`gl/texture.c:760`), and the
  handler above makes the slot dirty.

## LOW-2: BRDF raw-consumption exemption on an invalid BRDF stage. Cannot occur now.

`stage_consumed_raw` now requires `j >= 2` (`psh.c:2137`). A BRDF in stage 0
or 1 no longer exempts an earlier stage from #283's byte split.

## LOW-1: the footprint derivative includes the per-pixel tie bias. Still open (LOW).

This was not remediated, and it did not need to be for a fold. As pass 1 said,
the bias is a sub-texel epsilon. This can be a follow-up.

## New in the remediation

The only new behaviour is the dirty marking on `SET_SHADER_STAGE_PROGRAM`,
which costs a texture rebind when a mode changes. I found no new defect. The
measured configuration (2D PROJECT2D, BOX_LOD0) gets the same predicate value
as before. The stages whose `tex_aniso` changed from N to 1 never emitted the
probe loop, so the generated GLSL is the same for them, although their shader
key changes.
