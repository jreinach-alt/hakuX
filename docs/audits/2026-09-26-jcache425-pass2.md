## Pass-1 claims re-checked against the code

- **Buffer bound in `jc425_tick()`.** Each caller segment is 7 fields of
  `" xN="` (4 bytes) plus at most 20 digits, so 168 bytes. The loop guard
  `off < 512 - 160` admits a third segment only when `off <= 336`, which
  gives at most 504 bytes, under the 512-byte `buf`. `snprintf` never
  truncates, so `off` can never exceed `sizeof(buf)` and turn
  `sizeof(buf) - off` into a huge `size_t`. Holds.
- **No new dereference.** The classification reads `tb_cflags(tb)` and
  `jc->array[hash].pc`. The hit test just above it has already dereferenced
  the same `tb` (`tb->pc`, `cs_base`, `flags`, `tb_cflags`). Under
  `HAKUX_TCG68_JC=1`, a CF_INVALID TB left in the slot is therefore read no
  more than master already reads it. Holds.
- **Control flow unchanged.** Outside `XBOX`, `JC425_COUNT` expands to an
  empty statement. Inside `XBOX`, the `#ifdef` block only increments
  counters. The fill after a qht hit and both return paths are the same as
  on master. Holds.
- **All three callers pass `caller`.** `helper_lookup_tb_ptr`,
  `cpu_exec_step_atomic` and `cpu_exec_loop` all pass it, and the build
  (CI green) would reject a missed site. Holds.
- **Pixels.** The arms job's `[job.arms] VERDICT: PASS` on
  `jcache425-pixels-inert.json` reports 593/593 registered checks holding.
  This is the automated confirmation of what pass 1 took from NOTES.

## The LOWs

### L1: counters and a 2 s WARN line in every XBOX build. Still occurs; accepted

The code is unchanged, so the scenario from pass 1 can still happen. It stays
LOW because the precedent it follows is already on master:
`hakux_tlb68_tick()` (`accel/tcg/cputlb.c`) prints `[tlb68]` at WARN every
2 s, with no env gate, from the same call site. `[jc425]` adds a second line
of that kind. The hot-path cost is one increment to a static array per probe,
and both arms of every A/B pay it.

Carry this as follow-up. When the #425 lever lands (default JC on, filed as
`dispatch/board-requests/jcache425.md`), gate or remove `[tlb68]` and
`[jc425]` together, since gating one without the other buys nothing.

### L2: `perfsum.py` drops the logcat date. Still occurs; accepted

`ts()` still matches `MM-DD HH:MM:SS.mmm` and discards the date. The script
is a lane tool under `docs/lanes/jcache425/`. No shipped code or job reads
it, and none of the runs cited in NOTES crosses midnight.

### L3: `perfsum.py` also sums `w`, `dt` and `jc`. Still occurs; accepted

`re.findall(r'\b([a-z]+)=\d+', ...)` still picks up the header fields. The
effect is cosmetic, and the F2 ratios in NOTES come from the named counters.
