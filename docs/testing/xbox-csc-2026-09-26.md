## The rules

1. **The field is global.** When `SET_CONTROL0` bits 28-31 hold
   `CRYCB_TO_RGB`, every texture stage's output is converted. This holds for
   any format, and with no dependent read needed (B1).
2. **The converter is `util.h`'s `convert_ycbcr_to_rgb()`, with the red term's
   rounding constant at 128.**
   - Y comes from R, Cb from G and Cr from B. Alpha passes unchanged.
   - With kr = 128 it is exact on all 256 palette cells, which span 0..255 on
     every input. With kr = 127, 241 of 256 are exact.
3. **A YUY2 or UYVY texture reads out raw.** The fetch gives (R, G, B, A) =
   (the texel's own Y, the pair's Cb, the pair's Cr, 255). That is the
   converter's own input layout.
   - With the field off, that raw value is what the stage returns.
   - With the field on, `YUY2_On` and `UYVY_On` match hakuX's decode (kr 128)
     on 64 of 64 texels.
4. **The conversion comes after the texture shader.** The bump offsets and the
   luminance read the unconverted fetch.
   - `BumpS_On` and `BumpT_On` displace by -16 and +16, the same as with the
     field off. The converted source would give +0.25 and +26.25.
   - `Lum_On` is exact on 256 of 256 cells as follows: L is the raw R over
     255; the product is truncated; that product is then converted.
   - `Lum_Off` is exact on 256 of 256 cells as the truncated product. hakuX
     rounds it, the PR #168 finding.
5. **The bump matrix words land as s += w0·dS + w3·dT and
   t += w1·dS + w2·dT.** That is hakuX's existing swizzle. This run did not
   measure it; the G8B8 `_R90` goldens favour it, and it is recorded on #10.

## What hakuX does instead

- It decodes YUY2 and UYVY at upload whatever the field says
  (`texture.c:516`'s FIXME). With the field off it returns RGB where silicon
  returns (Y, Cb, Cr, 255).
- It drops the field (`DEF_METHOD(NV097, SET_CONTROL0)`, `pgraph.c:2590`). So
  a non-YUV stage is never converted.
- It takes a YUV bump source's offsets and luminance from the decoded RGB,
  where silicon uses the raw Y, Cb and Cr.
- It rounds the luminance product, where silicon truncates (PR #168).

These rules retire the reading at `texture.c:498-512` and in
`docs/investigations/bump-yuv-source.md`, that "hardware is not returning a
TEX1 cell at all". Hardware returns the cell, converted.
