## What is known (docs/lanes/cloud-282/NOTES.md, tie_rule.py)
Silicon has no sampler tie rule. On the checkerboard class a tie's direction is set by which triangle of the quad the
pixel is in, which axis it is on, and whether the draw is fixed-function: interpolator arithmetic. A rule fitted to that
predicts 95.2% of disputed tie pixels (ours today: 44.8%). The bump class is NOT a tie class: its edge shift changes
sign with the bump map's format. NOTES "What would move this forward" asks for a desktop model of NV2A attribute-plane
setup and evaluation, validated on an FF quad with exact v ties, before anything touches psh.c or vsh-ff.c.
