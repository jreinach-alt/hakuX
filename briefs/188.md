## What is already on master: read it before anything else

- `pmc_read` returns the constant `0x01110000` for `NV_PMC_ENABLE` (PR #198,
  `68a18b35d7`). `pmc_write` drops writes via `default`. The comment block at
  `hw/xbox/nv2a/pmc.c:64-100` explains both, and it is still right about why
  the write was left alone.
- PR #203 (folded `82e460e863`) is the measurement this brief rests on:
  `docs/testing/nv2a-probe-pmc-findings.md`, section "NV_PMC_ENABLE (0x200)". It
  establishes the following.
  - **Idle, no write issued:** `0x01110000` (bits 16, 20 and 24).
  - **After pbkit's all-ones write** (`pb_init()`, which every graphics title
    runs): `0x13111113`. So the **implemented bits are 0, 1, 4, 8, 12, 16, 20,
    24, 25 and 28**, ten of them, and every other bit ignores a 1. Settable is
    supported for 0, 1, 4, 8, 12, 25 and 28 (idle 0, then 1 after the write).
    Bits 16, 20 and 24 read 1 already, so settable and hardwired cannot be told
    apart for them.
  - **Which engine any bit gates is UNKNOWN.** Four implemented bits (0, 1, 20,
    25) are unnamed by envytools, and the all-ones write separates neither
    hypothesis. #203 says it outright: "Anyone implementing pmc_write for #188
    ... must treat the bit->engine map as unknown."
  - **The halt is explained.** Writing `0` (`NV_PMC_ENABLE_ALL_DISABLE`) is what
    stopped the console. Every graphics title writes `0xFFFFFFFF`, and
    `pb_kill()` writes the saved value back.

## The job

1. Give the register **storage**: reset value `0x01110000`, and a write stores
   `val & 0x13111113`. After `pb_init()` a guest then reads `0x13111113`, as
   silicon does under load. Today it reads `0x01110000`, which says "PFIFO and
   PGRAPH are down" at all times, mid-frame included.
2. **Gate nothing.** A write changes the stored word and has no other effect:
   no engine reset, no halt on 0. The bit->engine map is unmeasured, and
   modelling bit 12 as PGRAPH or bit 28 as PVIDEO would be modelling an
   assignment no measurement supports. Say so in the code, where the next
   reader will look.
3. Be explicit about the one model choice the data does not settle. After a
   write that CLEARS 16, 20 or 24, what reads back is unmeasured: hardwired-1
   or storage? Pick one, name it as a choice, and give it a falsifier in the
   comment.

## Proof

Extend `docs/testing/pmc_enable_selftest.{c,sh}` (the desktop-build test
#198/#211 use):

- the reset read is `0x01110000`;
- a write of `0xFFFFFFFF` reads back `0x13111113`;
- a write of `0x00001000` reads back `0x00001000` under your choice for 16/20/24,
  and the test states which choice it asserts;
- `pb_kill`'s restore round-trips.

Build a mutant per invariant and confirm each trips its check (unmasked
storage, constant read, write-dropped).
