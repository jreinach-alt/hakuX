# #120 -- fold waits forever on a PR with no CI run (cloud, no device)

Base: 05e25ca29b (origin/master).
Files: docs/testing/jobs/fold.sh, docs/testing/jobs/selftest.sh.
Issue: #120.

GOAL: `ci_green()` (fold.sh:51-58) maps an empty `statusCheckRollup` to
`NONE`. The caller (fold.sh:70-79) treats anything not `GREEN` as "wait"
but comments only on `RED`, so a `NONE` PR (usually `[skip ci]` in the head
commit) waits silently forever -- no lane can read `$WORK/logs/fold/tick.log`
on the host. Treat `NONE` like `RED`: comment once, naming `[skip ci]` in
the head commit as the usual cause and "push an empty commit to the head"
as the unblock, using the same `$F/failed/$pr-$head-ci` marker so it stays
one comment per head. Leave `RED` behaviour unchanged.

FALSIFIER: a PR whose head has `[skip ci]` and an empty statusCheckRollup
must get exactly one fold comment naming the cause; a second fold.sh run
against the same head must not comment again; a PR with a genuine RED
rollup must still get its existing RED comment, unchanged.

DONE WHEN: a `NONE` rollup produces exactly one comment per head; a
selftest case added to `docs/testing/jobs/selftest.sh` that fails against
the current fold.sh and passes after; `RED` behaviour unchanged. Needs no
device -- open a draft PR from lane/cloud-120 per roles/lane.md.
